3. **非阻塞状态机结构不得重构**（`ST_IDLE→TX→WAIT_RX→PARSE→SEND`）。**禁止 `delay()`**；`setup()` 内原有的 USB CDC 有界等待保留。
4. **收发顺序不得改**：清 RX 必须在 `Serial1.write()` 之前，然后 `flush()`。
5. **UART 引脚与参数不得改**：`Serial1.begin(9600, SERIAL_8N1, 20, 21)`；`RS485_DE_PIN = -1`（MAX13487，EN 固定高，**不得动态切换**）。
6. **`RS485_MODE_LOOPBACK_SELFTEST` 保持 `0`**，该分支代码保留不动。
7. **只读不写**：不得出现任何合闸 / 分闸 / 锁扣 / 解锁 / 复位 / 写寄存器 / 广播帧。
8. **不得引入第三方库**。⚠️ 本批次**允许**使用 ESP32 Arduino core **自带**的 `WiFiUdp` / `time` / `HardwareSerial`（已在用），以及**新增** `ArduinoJson`？——**不允许**。
   ⇒ **JSON 必须手写 `snprintf` 组装**（与老师一致：他固件里就是格式串 `"%s":%u` 拼出来的，没有 JSON 库）。
9. **`secrets.h` 编译期守卫保留**。
10. **只提交自己负责的文件**。

### 本批次新增的三条硬约束

## 三、批次 1 · 详细规格

### 3.1 数据行（每轮三段全成功时发一行）

**字段顺序照抄**（与 `02_docs/17` §3 的原文格式串一致，便于日后与老师的数据并表）：

```
{"seq":<u32>,"dev":"ESP485-<6HEX>","mac":"<MAC>","ip":"<本机IP>","ts":"<ISO8601>","ts_ok":<true|false>,
 "openState":"<%04X>","record1":"<%04X>","record2":"<%04X>","record3":"<%04X>",
 "frequent":<f1>,"leakage_current":<f3>,"N_temp":<d>,
 "A_temp":<d>,"A_voltage":<d>,"A_current":<f2>,"A_Pf":<f2>,"A_power":<d>,"A_Q":<d>,"A_S":<d>,"A_H":<d>,"A_L":<f3>,
 "B_temp":<d>,…,"C_temp":<d>,…,
 "power":<d>,"Q":<d>,"S":<d>,"H":<d>,"L":<f3>,
 "quality":"OK|PARTIAL","invalid":"<无效字段,逗号分隔>","seg":"<0|3>","raw":"<78 字节 HEX，空格分隔，固定 233 字符>"}
```

> 📌 `seg` 的取值只有两个：**`"0"` = 一帧读全**、**`"3"` = 三段读取**。
> ⚠️ **【勘误注 2026-10-07 砚青】本条已被批次 2 取代**：seg 一帧读全改为 **`"1"`**（"0" 弃用，见 `04_ai_prompts/06` §2 P5 与 `config.h` 的 `QI_SEG_TAG_MODE_FULL`），且 seg 改为**运行时判定**（心跳行另有 `mode` 字段）。本文件其余内容为批次 1 历史指令，原文保留。
> （`QI_READ_SPLIT_3SEG=1` → `"3"`；`=0` → `"0"`。**不存在 `"1"`** —— 早先版本写 `<0|1|3>` 是笔误，Codex 已指出，此处更正。）
> 📌 `queue` / `dropped` 本批**固定 0**；这是"**本批没有队列**"，**不代表队列健康**。

**换算口径**：一律以 **`05_hardware/STB3-125_字段字典.csv` 的 `conv` 列为准**（`raw/10`、`raw-40`、`(H*65536)/1000+L` …）。
⚠️ 电量公式按文档写 `(H*65536)/1000 + L`，并在代码注释里注明「**该式存疑**，若设备语义是 32 位累加器（0.001 度）则应为 `(H*65536+L)/1000`，两者差 1000 倍」（见 `06_tests/db_proto.py` 文件头）。

### 3.2 心跳行（每轮都发，独立一类）

```
{"seq":<u32>,"dev":"ESP485-<6HEX>","ts":"<ISO8601>","ts_ok":<bool>,"type":"hb",
 "rssi":<d>,"free_heap":<u32>,"poll_ok":<u32>,"poll_err":<u32>,"udp_tx":<u32>,"queue":<u32>,"dropped":<u32>}
```

**两类行的关系**（**必须明确，这是本次唯一的"行为变更"**）：

| 本轮结果 | 发什么 |
| --- | --- |
| 三段全成功 | **数据行 1 行** |
| 任一段失败 | **心跳行 1 行**（原 `FAIL:Sx:原因` 不再单独成行，但**失败原因必须写进串口日志**，且计入 `poll_err`） |

> ⚠️ 这一条**修改了上一轮 P13 的行为**（原来失败发 `FAIL:Sx:原因`）。**改动理由**：对齐老师的两类行模型；
> **代价**：拔掉 USB 时现场看不到失败原因。⇒ **必须用计数器补偿**：`poll_err` 递增 + **串口日志保留 `FAIL:Sx:原因`**。
> 若总控认为现场可观测性更重要，可保留「失败时额外发一行 `{"type":"err","seg":"S2","reason":"TIMEOUT"}`」—— 请**在回报里给出你的建议**。

### 3.3 设备命名

- `dev` = `"ESP485-"` + **MAC 后 6 位十六进制大写**（例：MAC `48:F6:EE:15:9B:88` → `ESP485-159B88`）。
- `mac` = 完整 MAC（`WiFi.macAddress()` 的默认写法，冒号分隔大写）。

### 3.4 为什么必须保留 `raw`（**不要"优化"掉**）

老师的 JSON **只有工程量、没有原始值** ⇒ **他的历史数据不可重算**（公式一改只能重采）。
我们**多给一个 `raw` 字段**：JSON 接收端按名取值，多一个字段**不破坏兼容**，但换来
**公式可演进 + 历史可重放**。这是本项目相对参考实现的核心改进之一（`02_docs/16` §9.4）。

### 3.5 累计计数器

| 计数器 | 含义 |
| --- | --- |
| `poll_ok` | 三段全成功的**轮数**（不是段数） |
| `poll_err` | 至少有 1 段失败的**轮数** |
| `udp_tx` | UDP 发送**成功**的次数（`beginPacket`/`endPacket` 都返回 1） |
| `queue` / `dropped` | 预留；本批**固定发 0**（本批不引入队列） |
| `free_heap` | `ESP.getFreeHeap()` |
| `seq` | 每发**一行**（数据行或心跳行）自增 1，`uint32_t` 回绕正常 |

### 3.6 缓冲区

`g_payload` 目前 `char[384]`。**数据行加上 `raw`（78 字节 → 233 字符 HEX）后最长约 900 字节**
⇒ **必须把缓冲扩到 ≥1024**，并且沿用现有的"snprintf 返回值 ≥ sizeof 就告警"的检查。

### 3.7 时间戳

- `ts` 用 **ISO8601**：`strftime("%Y-%m-%dT%H:%M:%S")`。
- `ts_ok` = 本轮会话**确实收到过 NTP 回包**（沿用现有 `ntpHasReply()` 判据，**不要改回 `getLocalTime()`**）。
- 未同步时 `ts` 仍要填（用 `BOOT+<秒>` 或 `1970-01-01T00:00:00`），**并把 `ts_ok` 置 false** —— **字段不许缺**。

### 8.2 🔴 需补的 3 项（请在**本次烧录之前**一起改完，可省一次断电窗口）

#### ① 🔴 最重要：`A/B/C_temp == -40` **不能进 `invalid`** —— 否则 `quality` 永远是 `PARTIAL`

**现象**：你在 `buildDataJson()` 里把 `pTemp[i] == -40` 判定为无效并 `addInvalid`（第 567~569 行）。
但该型号设备**恒不上报接线柱温度**（`raw` 恒为 0 ⇒ 恰为量程下限 −40，真机与老师的设备都是如此）。
⇒ **每一行数据的 `invalid` 都非空 ⇒ 每一行的 `quality` 都是 `PARTIAL`** ⇒ `quality` 字段**彻底失去区分度**。
（WorkBuddy 在做落库原型时**踩过同一个坑**并已修正：修正前后是 `OK=0/PARTIAL=6` → `OK=6/PARTIAL=0`。
见 `02_docs/16` §6 的「A3 的一个关键设计」。）

**要求**：把「**该型号已知不上报**」与「**本次异常**」分开。

| | 判定 | 是否进 `invalid` | 是否影响 `quality` |
| --- | --- | --- | --- |
| `<A\|B\|C>_temp` **恰好等于 −40** | **已知不上报** | ❌ 不进 | ❌ 不影响（仍可 `OK`） |
| `<A\|B\|C>_temp` 越界（< −40 或 > 160） | 本次异常 | ✅ 进 | ✅ 降为 `PARTIAL` |
| 其它字段越界 | 本次异常 | ✅ 进 | ✅ 降为 `PARTIAL` |

**做法（推荐）**：加编译期宏 `#define QI_PHASE_TEMP_ABSENT 1`（默认 1 = 该型号不上报接线柱温度）。
该宏为 1 时，`== -40` 走"已知不上报"分支；为 0 时退回当前行为。
（这样与 `06_tests/db_proto.py` 的 `--known-missing` 口径一致。）
**可选**：若想把信息留痕，可在数据行末尾追加 `"no_sensor":"A_temp,B_temp,C_temp"` —— 但**不要**靠它改 `quality`。
