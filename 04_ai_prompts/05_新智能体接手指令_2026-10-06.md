# 1. 项目目标与背景

**要解决什么**：现有架构用树莓派（500–800 元/台）作中间数据采集网关，节点一多成本就崩。目标是改用 **ESP32-C3 SuperMini（约 50 元）+ MAX13487 RS-485 模块** 重写这个网关，先在面包板上跑通原型机。

**链路**：

```
STB3-125（QI 用电采集设备，RS-485 / Modbus RTU，只读）
   ↓  ① ESP32 每秒轮询一次
ESP32-C3（加时间戳 + 组 JSON）
   ↓  ② UDP 192.168.1.113:8888（电脑侧）
电脑（先用 NetAssist / Python 收包，后续落库）
```

**最终要交付**：一个能连续稳定采集、数据可入库、成本只有树莓派 1/10 的网关节点。

**工程分五阶段、七个关卡**：阶段三「分模块验证」的 **M0–M5 已全部通过**；现在在「功能对齐」（对齐导师组里另一位老师已跑通的一版参考实现），之后是 **M6 系统压测 → M7 验收结项**。

# 2. 我用的思路、方法与关键决策（**这些是已定的，别推翻**）

1. **先软后硬、先模拟后真机**：每个关卡都在电脑端造一个"假设备"把代码跑通，再碰真机 —— 目的永远是**把"代码问题"和"真机问题"分开**。
2. **固件只搬运原始值，不做工程量换算**。换算放在电脑 / 服务端。
   - 理由：公式以后会改，原始值留着就能重算；`raw`（78 字节 HEX）必须留在上报里。
   - **这是本项目的商业化优势**，不要以"简洁"为名优化掉。
3. **上行改成 JSON**（对齐参考实现）：每轮发 **2 行** ——
   - 成功轮：心跳行 `type:"hb"` + 数据行
   - 失败轮：心跳行 `type:"hb"` + 失败行 `type:"err"`
   - 所以 **`seq` 每轮 +2**（不是 +1，很多人会算错）。
4. **设备命名** `dev = "ESP485-" + MAC 后 6 位`；另有累计计数器 `poll_ok / poll_err / udp_tx`。
5. **分批推进，不一次全做**：批次 1（JSON 上行）→ 批次 2（一帧读全 + 失败降级）→ 批次 3（AP 热点 + Web 配置页 + `/status` + NVS）。每批**可独立验证**才做下一批。
6. **角色分工 = "作者 ≠ 验证者"**：谁写的改动，由另一个角色复核后才烧录 / 定案。**AI 不自己给自己签字。**
7. **文档都能改，但改完必须留痕**（本项目 2026-10-06 刚改过铁律，见第 5 节）。
8. **工具链：编译 + 烧录只走 Arduino 工具链**（`arduino-cli`）。`01_firmware/pio_verify/` 里的 PlatformIO **只用来做对照编译，不烧录** —— 因为它默认给的是 arduino-esp32 **2.0.17**，而板子上跑的是 **3.3.10**，**换 core 产物必然不同**。

# 5. 约束、红线与易错点（**踩过的坑，逐条看**）

## ⚠️ 硬件安全红线（最高优先级，任何情况不得为进度让步）
1. **真机带电期间，ESP32 的 USB 数据线必须拔掉**，改用**充电宝**供电 —— 否则电脑与配电箱经 USB 地 + 485 共模构成接地回路，**会烧电脑主板**。
2. **开箱接线前必须断电 + 验电**（"断电 ≠ 无电"）；**没有万用表 / 验电笔不许开箱**；首选请老师或电工断电接线。
3. **每次改接线前都要再断一次电** —— "装的时候断电了" ≠ "此后一直安全"。
4. **STB3-125 只读不写**：合闸 / 分闸 / 锁扣 / 解锁 / 复位 / 写寄存器 / 广播 **一律禁止执行**。
5. 接线细节：485 模块**按字母接不按位置**，总线侧顺序是 **`B` → `A` → `GND`**；`TXD`/`RXD` 是**交叉**约定（`GPIO21`→模块 `RXD`、`GPIO20`←模块 `TXD`）—— 同名对接会**双向全断**，而模块电源灯还是亮的，极易误判"模块坏了"。

## 🔧 操作上的易错点
12. **编译 / 烧录前必须让我关掉 Arduino IDE 的串口监视器**（进程 `serial-monitor` 占着 COM 口，否则报 `PermissionError(13)`）。
13. **打开 COM5 会复位 ESP32**（拉 DTR/RTS 触发硬复位）⇒ 抓串口会**清零计数、打断采样**；判断 UDP 收包速率前先等建链 5~10 秒。
14. **UDP「发送成功」≠ 数据送达**（无连接，目标 IP 不存在时静默丢弃）⇒ 必须在电脑侧用 `06_tests/udp_listen.py` 确认真收到。开机 / 网络收敛期的"发送失败"是**暂态**。
15. **电脑 WLAN IP 漂得很勤**（`.117` → `.118` → `.113`）⇒ **每次开工前先让我跑 `ipconfig /all`**，不一致就同步 `config.h` 的 `UDP_TARGET_IP`。认准 WLAN，别认 VMnet 虚拟网卡。
16. **别把 `0x03` 和 `0x04` 混用**：`0x03` 读的是保持寄存器 = 设备配置值，会产出**看起来正常但语义完全错误**的数据（静默失败）。真机一律 `0x04`。
17. **两行的 `seg` 语义不同**：数据行的 `seg` 是**读取模式**（`"3"`），失败行的 `seg` 是**失败段**（`"S2"`）。解析和落库时**不能当同一个字段**。
18. **超时档位**：首字节 80 ms / 字符间隔 **`RS485_CHAR_TIMEOUT_MS = 8`**（M4 期间曾临时放到 25，M5 起已收回）/ 整帧兜底 300 ms。**字符间隔 ≠ 整帧上限**，兜底不建议小于 120 ms。
19. **时区串不能加尖括号**：`configTzTime("CST-8", ...)` 正确；`"<CST-8>"` 会被当字面量 ⇒ **差 8 小时**。SNTP 必须在 WiFi 连上之后初始化。
20. **NTP 三源**：主 `172.16.0.2`（校内 chrony）→ 备1 `ntp.aliyun.com` → 备2 `203.107.6.88`。**公网备源必须保留** —— 网络退路是手机热点，那时内网源必然不可达。
21. **工具链是 `esp-rv32`**（ESP32-C3 是 RISC-V），不是 `esp-x32`。
22. **不确定的一律标 `[待确认]`**。目前仍开着的：电量公式两解（差 1000 倍）、`record1/2/3` 的 `0` 与 `F` 之别、`quality` 编码、温度量程口径（`db_proto.py` 算 −80…120 ℃，固件用 −40…160 ℃，**至少有一个要改**）、PlatformIO 的 core 未定。清单见 `PROGRESS.md` §8.1。
