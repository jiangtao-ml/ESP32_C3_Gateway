## 2. 文件就位（**目录结构必须一模一样，不能拍平**）

在旧机建一个根目录，例如 `C:\esp32_collect\`，然后**严格按这个层级**放置：

```
C:\esp32_collect\
├── 05_hardware\
│   └── STB3-125_字段字典.csv        ← 必需
└── 06_tests\
    ├── udp_collect.py               ← 必需（主程序）
```

⚠️ **为什么不能拍平**：`db_proto.py` 第 42–43 行按相对路径找字段字典 ——

```python
ROOT = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))   # 06_tests 的上一级
```

## 3. 环境配置（按顺序做，每步把结果记下来）

### 3.1 Python

```bat
python --version
```

要求 **≥ 3.8**，建议 **3.11 / 3.12**（自带 SQLite ≥3.35，满足脚本要求）。
若未装：官网下载 Windows installer，勾选 **Add Python to PATH**。

> ⚠️ **Python 3.13 有一个必看的坑（已在 2026-10-26 修掉，但你要确认修过）**
> 3.13 起 `threading.Thread` 会在实例上挂一个叫 `_handle` 的属性，把收包类里**同名的
> 回调方法整个遮蔽掉**。后果不是报错退出，而是：**`rx` 恒为 0、日志里只有 sporadic
> `PARSE_EXC` 告警，看起来和"抓不到包 / IP 配错 / 防火墙拦了"一模一样**，
> 8 小时和 168 小时都会跑出一份空报告。
> 规避方式 = 回调已改名 `_on_datagram`；`--env-check` 里加了一条硬项「收包回调可调用」，
> **必须看到这条是 [信息] 绿色通过**，看不到或报 [阻断] 就不要起跑。
> 如果你是 3.11/3.12，本来就不受影响，但这条自检同样必须过。

### 3.2 电源（**这条最容易漏，漏了 8 小时白跑**）

控制面板 → 电源选项 → 更改计划设置：

- 关闭显示器：**从不**
- 使计算机进入睡眠状态：**从不**
- 更改高级电源设置 → 硬盘 → 关闭硬盘时间：**从不**
- 更改高级电源设置 → USB 设置 → USB 选择性暂停：**已禁用**

命令行也可以：

```bat
powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
powercfg /change monitor-timeout-ac 0
powercfg /change disk-timeout-ac 0
```

⚠️ 若是笔记本，还要确认**合盖不休眠**、**拔掉电源也不会切省电**。

### 3.3 关闭自动更新重启

```bat
sc config wuauserv start= disabled
```

（跑完长跑后可以改回 `demand`。）
另外确认"活动时间"里没有待安装的更新。

### 3.4 防火墙放行 UDP 8888 入站

```bat
netsh advfirewall firewall add rule name="ESP32_UDP_8888" dir=in action=allow protocol=UDP localport=8888
```

### 3.5 记录本机 IP（**这个必须回传给我**）

```bat
ipconfig
```

记下**有线网卡**的 IPv4。**ESP32 的上报目标要改成这个 IP，所以这个地址是后续所有步骤的前提。**

> **网段说明（2026-10-26 21:05 实测更新）**：不要假设一定是 `192.168.1.x`。
> 实测这台旧机在 **`172.16.0.138`（网关 `172.16.0.2`）**，而 ESP32 在 `192.168.1.200`。
> **两个网段不同但路由可达** —— 从 ESP32 所在网段 ping `172.16.0.138` 得 1.75 ms（走默认网关），
> 且本方案是**单向 UDP 上报、无回程**，所以跨网段不影响。
> 改 IP 由主控在 ESP32 侧做（`/save`，无需插 USB），你不需要动 ESP32。
>
> ⚠️ **`172.16.0.138` 如果是 DHCP 分到的地址，长跑中途换 IP 会导致后面所有数据丢失。**
> 请确认它是静态配置或已在 DHCP 服务器上做保留；能固定就固定。

### 3.6 本机时间必须准确（**新加，漏了会让时间序列整体平移**）

```bat
w32tm /resync
w32tm /query /status
```

要求：与 `time.windows.com` 同步成功，**本机时间误差 < 5 秒**。

为什么要管这个：ESP32 在"还没对时成功"的阶段发的是 `BOOT+<秒数>`（不是时间戳），
接收端靠「首包到达的本机时刻 − BOOT 秒数」反推开机时刻。**本机时钟一旦偏了，
整个世代的所有 `collect_time` 会一起平移，而报告里看不出任何异常**（因为每行都自洽）。

新版本已内置检测：运行中若发现本机时间与固件 NTP 时间相差 > 5 s，
会记一条 `HOST_CLK_SKEW` 事件（10 分钟最多一条）。
**如果你在日志里看到 `[CLK] 本机时钟与固件差 xxx s`，立刻停下来校时，不要继续跑。**

## 4. 自检（必须全绿才能起跑）

```bat
cd /d C:\esp32_collect\06_tests

python udp_collect.py --env-check
python udp_collect.py --selftest
```

`--env-check` 正常输出**应该是这样**（顺序可能略有差异）：

```
  [信息] Python 3.x.y
  [信息] 收包回调可调用          ← ★ 必须出现这一行
  [信息] SQLite 3.4x.x
  [信息] 磁盘剩余 xx GB
  [信息] 介质 = 本机固定盘（FIXED）
  [信息] 字段字典 OK（39 行）
  [信息] UDP 8888 空闲
  ...
结论：通过
```

必须出现的三条硬信号：
1. **`收包回调可调用`** —— 缺了就是 Python 3.13 那个坑没修，跑了也是 0 包。
2. **`介质 = 本机固定盘（FIXED）`** —— 若报 `网络盘 / 可移动盘 / 云同步盘`，
   **必须换路径**，否则 SQLite 会在几十小时后突然 `disk I/O error`。
3. **`结论：通过`** —— 有任何 `[阻断]` 都不许起跑。

`--selftest` 应该以 `✓ 全部一致，引擎可复现注入值` 结尾，**不需要设备**。

> 说明（2026-10-26 更正）：**旧版说"Win10 上文件系统检查会自动跳过、这是正常的"——那句已作废。**
> 现在 Windows 会真的检查盘符类型和云同步目录，报错就是真有问题，不许忽略。

**如果 `--env-check` 报 SQLite < 3.24** ⇒ Python 版本太旧，换 3.11/3.12。

## 5. 起跑（先跑 8 小时，不是 168）

```bat
cd /d C:\esp32_collect\06_tests

python udp_collect.py --db C:\esp32_collect\data\run8h.db --hours 8 --fw-ver 0.6.0-batch3
```

| 参数 | 说明 |
| --- | --- |
| `--db` | 数据库路径，**本机磁盘**，目录会自动创建 |
| `--hours 8` | 计划时长。第一阶段只跑 8 小时 |
| `--fw-ver` | 固件版本标识，写进 `collect_run` 表 |
| `--port` | 默认 8888，不用改 |

⚠️ **起跑前必须确认 ESP32 已经把上报目标改成这台机器的 IP** —— 否则你会一个包都收不到。这一步由主控（新电脑那边）操作，**你不要动 ESP32**。

## 6. 怎么判断真的收到了

起跑后 10 秒内，控制台应出现持续的对数行。若 60 秒仍无任何数据：

| 现象 | 排查 |
| --- | --- |
| 完全无包 | ESP32 目标 IP 没改成这台机器 / 不在同一网段 / 防火墙拦了 |
| **统计行 `rx 0` 但日志里有 `PARSE_EXC`** | **Python 3.13 的 `_handle` 遮蔽坑**（见 §3.1）。跑 `--env-check`，看有没有"收包回调可调用" |
| 有包但很少 | WiFi 弱或丢包，看报告里的送达率 |
| 报 `disk I/O error` | DB 放到了网络盘 / U 盘 / 共享目录 |
| 日志出现 `[CLK] 本机时钟与固件差 xxx s` | 本机时间不对，立刻停下校时（见 §3.6） |
| 统计行 `d 0` 但 `h` 正常增长 | 只收到心跳、数据行全被判 unknown ⇒ 固件侧格式异常，回传日志给主控 |

## 7. 停止（必须优雅停止，不要直接关窗口）

```
Ctrl + C
```

脚本会排空缓冲、写报告、关闭 DB。

⚠️ **三条禁令**（2026-10-26 实测补充）：
1. **不要点窗口右上角的 ✕** —— 那是硬杀进程，`stop_signal_at` / `ended_at` 都不会写，
   报告根本不会生成。
2. **不要用任务管理器"结束任务"** —— 同上。
3. **不要直接断电** —— WAL 里的数据会丢。

判断"优雅停止成功"的唯一标准：控制台最后出现
```
[RUN] 报告已写入 C:\esp32_collect\data\run8h_report.txt
```
**看不到这一行 = 停止方式不对，必须重来。**（这是 G0-0.7 门禁项）

## 9. 🚨 安全前置（必须由用户/老师确认已知晓，你只负责知情）

这台机器同时承担两个角色：**ESP32 的 USB 供电电源** + **数据接收端**。

- ESP32 的 USB 地 → 这台电脑主板地
- ESP32 的 485 GND → 带电配电箱的地
- **两者之间存在共模电位差**，极端情况下电流会经 `配电箱地 → 485 GND → MAX13487 → ESP32 → USB → 主板` 回流

**这条风险已由主控向用户明确指出，由用户与老师决策承担。**
你能做的、也必须做的：

1. **绝不在 ESP32 运行期间插拔任何 485 接线**
2. **绝不用这台机器的 USB 口给 ESP32 烧录固件**（烧录必须等配电箱断电）
3. 发现 ESP32 异常发烫 / 异味 / 电脑 USB 口异常 → **立刻拔 USB 并通知用户**
