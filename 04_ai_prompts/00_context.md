【项目全景上下文包：ESP32-C3 替换树莓派网关项目】

一、项目背景与目标

- 背景：现有架构使用树莓派（成本500-800元）作中间数据采集网关，数量多导致成本过高。
- 目标：使用 ESP32-C3 SuperMini（约50元）+ MAX13487 RS-485模块 替换树莓派，重写架构，先在面包板上跑通原型机。
- 角色分工：
  - 用户：负责硬件接线、烧录、看现象和提供日志。
  - 总控AI：负责拆解任务、写提示词、审查代码和排障。
  - Codex：负责在工程目录写/改代码、编译。
  - WorkBuddy：负责查资料、写文档、整理测试用例。

二、系统架构与数据流

1. 底层设备：QI 用电数据采集设备（约300元），支持 RS-485 通信，Modbus RTU 协议。
2. 中间网关：ESP32-C3 SuperMini + MAX13487 485模块（轮询采集、加时间戳、UDP上传）。
3. 上层接收：电脑上的“网络调试助手”通过 UDP 协议接收数据。

三、硬件清单与接线规范（⚠️ 致命警告）

- 主控板：ESP32-C3 SuperMini（工作逻辑电压 3.3V，使用 HardwareSerial(1)，RX=GPIO20，TX=GPIO21）。主控板 PCB 型号为 HW-466AB（板载标签）。
- 扩展底板：HW566 V0.0.1 扩展板（提供 5V、3.3V、锂电池供电接口）。面包板原型阶段（阶段三）先不使用 HW566，直接由电脑 USB 给 ESP32-C3 供电、由 SuperMini 的 5V 引脚给 MAX13487 供电；HW566 留到成品阶段（阶段四/五）上锂电池时再用。此决定已由总控确认。
- 通信模块：RS-485 模块（主芯片型号待实物丝印复核，见第五节待确认盲区）。若为 MAX13487 / MAX13488：+5V 供电，AutoDirection 自动方向控制，无需 DE/RE 控制引脚；若为 MAX485 / MAX3485：EN 即方向控制脚，必须由 GPIO 动态切换（固件已内建 `RS485_DE_PIN`，默认 -1 不启用）。
- ⚠️ 致命接线警告（必须遵守）：
  1. 共地：ESP32、MAX13487、USB转485模块、电源，所有 GND 必须连在一起。
  2. 电平转换（极其重要）：MAX13487 的 RXO 输出是 5V 电平，绝对不能直接连 ESP32 的 RX (GPIO20)。必须加电阻分压。正确分压：1kΩ接RXO，2kΩ接GND，交点接GPIO20（电压约3.33V）。严禁使用 2k接RXO，1k接GND（电压仅1.67V，ESP32无法识别高电平）。（模块侧该脚术语统一为 RXO；部分手册记作 RO / RXD，同一引脚。）【Q-10 实测口径（2026-10-03 补充）】上电前必须先用万用表实测 RXO 空闲电平：实测为 5V 时必须按上述 1kΩ/2kΩ 分压；实测为 3.3V 时直连 GPIO20、不再分压（分压后约 2.2V 低于 ESP32-C3 的 VIH≈2.475V，会把高电平判成低电平）。未实测前一律按 5V 处理（必须分压），严禁直连。与任务书 §5.2 第 2 条、README §6.2 第 2 条口径一致。
  3. 供电：MAX13487 必须接 5V，ESP32-C3 接 3.3V。（⚠️ 该电压随实物型号而变：三合一款中的 MAX3485 变体为 3.3V，MAX485 / MAX13487 为 5V。实物芯片丝印未经核实前，禁止盲目按 5V 接线。）
  4. 总线偏置：商品页仅注明「具有 120 欧匹配电阻」；4.7kΩ 偏置电阻未经实物核实 —— 按总控裁定，M3 须实测终端/偏置并联数量后回写本条。⚠️【2026-10-03 数据手册核实】MAX13487E 官方数据手册“Pullup and Pulldown Resistors”一节明确：**A/B 线上的上拉/下拉偏置电阻是器件正常工作的必要条件**（原文 “required for proper operation of the device”）——AutoDirection 依赖它们把总线拉到 A-B > 200mV 才能在发送结束后切回接收；总线若无偏置，状态机会持续保持驱动器使能、占死总线，从站永远无法应答。故 M3 的“偏置电阻实测”不是可选项而是**功能项**：实测若模块未焊 4.7kΩ，必须外部补（A 上拉 4.7kΩ、B 下拉 4.7kΩ）。数据手册原件已入库 `05_hardware/MAX13487E_MAX13488E_Datasheet.pdf`。
  5. EN引脚：⚠️ **接法随实物主芯片型号二选一 —— 接线前必须先用放大镜读模块上 8 脚芯片丝印定型**：① **MAX13487 / MAX13488（5V 双向，芯片无 DE 脚，靠 AutoDirection）** → EN 接**固定高电平**（首选模块 VCC/5V，3.3V 亦可），**不得悬空、不得接 GND、不得动态切换**（悬空若对应 SHDN# 会关断器件，症状正是 RX=0）；② **MAX485 / MAX3485（单向半双工，EN 即方向控制脚）** → EN **必须接 GPIO** 由固件按收发切换，**严禁固定接高**（常使能会占死总线、并与从站驱动冲突）。用户 2026-10-03 口述实物为 MAX13487、老师亦称 MAX13487（「不要切换 EN 引脚」= 接固定电平、不要动态切换），但商品页为三合一款、渲染图丝印为 MAX485 ESA，页面图不能代表实物 —— **故以丝印复核结果为准**；丝印未读前不要给 EN 接任何电平。【2026-10-03 数据手册核实】MAX13487E/MAX13488E 官方数据手册（Rev 3, 2024，已入库 `05_hardware/MAX13487E_MAX13488E_Datasheet.pdf`）Pin Description：**1 RO / 2 RE / 3 SHDN / 4 DI / 5 GND / 6 A / 7 B / 8 VCC，全片无 DE 引脚**（DE 为内部信号，RECEIVER_ENABLE = DRIVER_ENABLE 的反相，可被外部 RE 引脚覆盖）。手册口径：RE 高 = 交给 AutoDirection 状态机控制（热插拔默认态，正常收发）；RE 低 = 强制 RO 常开；SHDN 高 = 正常工作，SHDN 低 = 关断。故 ① 的“EN 接固定高电平”在手册 RE / SHDN 两种诠释下**均成立**，已由官方手册核实。【2026-10-03 商品页佐证】购买页对 MAX13487 变体明示「不能通过 EN 脚切换方向，不然烧坏电脑，后果自负」，与 ① 的「不得动态切换」一致；同页仅注明「具有 120 欧匹配电阻」，未提 4.7kΩ 偏置 —— 偏置是否板载见三.4，必须实物核实。

四、软件功能需求（1秒循环任务）

1. 联网：连接 WiFi，SSID = <占位符>，密码 = <占位符>。实际值放 01_firmware/esp32c3_gateway/secrets.h，.gitignore 已忽略。
2. 时间同步：通过 NTP 服务器（ntp.aliyun.com）同步时间，时区设置为东八区（UTC+8），获得准确的本地时间。
3. 485 通信：波特率 9600（已确认为最终值），8N1。若实物为 MAX13487 则 AutoDirection 自动收发、无需方向控制引脚；若为 MAX485 / MAX3485（丝印未复核前不得假定）则须由 GPIO 切换 EN（固件已内建 RS485_DE_PIN 开关）。
4. 1秒定时循环（使用 millis() 非阻塞实现）：
   - 4.1 向 485 总线发送 Modbus RTU 查询指令（测试帧（功能码 0x03，仅用于链路回环自测）：{0x01, 0x03, 0x00, 0x00, 0x00, 0x02, 0xC4, 0x0B}。QI 真实读取命令（功能码 0x04）：读全部参数 {0x01, 0x04, 0x00, 0x00, 0x00, 0x27, 0xB0, 0x10}，读 A 相电流 {0x01, 0x04, 0x00, 0x09, 0x00, 0x01, 0xE1, 0xC8}。真实协议见 05_hardware/STB3-125_Modbus_Protocol.doc）。
   - 4.2 接收 485 设备回复数据（两级超时 + 帧长驱动：首字节 80ms、字符间隔 4ms，收满预期帧长即止；300ms 仅作整帧兜底，避免死循环）。
   - 4.3 解析回复数据（Modbus 协议解析），拼接 ESP32 当前时间戳（格式：YYYY-MM-DD HH:MM:SS | HEX数据）。
   - 4.4 通过 UDP 将数据发送到电脑网络调试助手（目标 IP 暂用 192.168.1.117 —— 这是**电脑侧**接收地址；192.168.1.200 是 **ESP32 自身**固定 IP，勿混用。UDP 端口 8888（M2 起 NetAssist 实测可用，已定为项目最终值）。两者均需在阶段二固化为常量并在 README 第 8 节跟踪）。
   - 4.5 等待下一次 1秒定时触发。

网络环境与裁定（2026-09-27 追加）

网络环境（实测）：

- 学校统一管理 WiFi，无路由器后台权限；无需网页登录（ESP32 可直连）；手机 2.4GHz 热点退路可行。
- 电脑 WLAN：192.168.1.117 / 255.255.255.0 / 网关 192.168.1.1 / 网段 192.168.1.0/24。
- 唯一剩余风险：客户端隔离（AP isolation）是否开启 → M1 用 ping 192.168.1.200 实测（R-11）。

总控裁定：

- Q-02 主方案：ESP32 连学校 WiFi，用 WiFi.config(192.168.1.200, 192.168.1.1, 255.255.255.0, 192.168.1.1) 固定；退路=手机 2.4GHz 热点。M1 前置：ping + arp -a 确认 192.168.1.200 空闲；WiFi 分析 App 确认 SSID 在 2.4GHz 独立可连。
- Q-05：手写帧组装（不用第三方 Modbus 库）。
- Q-11：已闭环（RXO 术语已统一）。
- Q-12：同秒时间戳不加毫秒、不加序号。
- NTP 网络风险（M2 前置）：校园网可能屏蔽 UDP/123 或不下发外部 DNS；失败时改用 IP 直连 203.107.6.88，仍不通退手机热点。
