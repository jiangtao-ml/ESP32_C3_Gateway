## 一、硬约束（**不得改动**，与上一轮一致）

1. **NTP 三源值不得动**：`NTP_SERVER_1/2/3` = `172.16.0.2` / `ntp.aliyun.com` / `203.107.6.88`；`NTP_TZ_INFO` 必须仍是 `"CST-8"`（**不得加尖括号**）。
2. **`UDP_TARGET_IP` 已由 WorkBuddy 依用户指示改为 `192.168.1.114`**（2026-10-05 实测）。⚠️ 若开工前 `ipconfig /all` 显示又漂了，**先报告再改**，不要自行决定新值。
3. **非阻塞状态机结构不得重构**（`ST_IDLE → ST_TX → ST_WAIT_RX → ST_PARSE → ST_SEND`）。**禁止 `delay()`、禁止在 `ST_TX` 里用 while 连发三段** —— 三段必须由状态机**多轮推进**完成（同一秒内跑完 3 个"发-收-解"子回合）。
4. **收发顺序不得改**：清 RX（`while (Serial1.available()) read()`）**必须在 `Serial1.write()` 之前**，然后 `flush()`。
5. **UART 引脚与参数不得改**：`Serial1.begin(9600, SERIAL_8N1, 20, 21)`、`RS485_DE_PIN = -1`（MAX13487，EN 固定电平，**不得动态切换**）。
6. **`RS485_MODE_LOOPBACK_SELFTEST` 保持 `0`**；该分支的代码**保留不动**（串口层回归还要用）。
7. **时间戳格式不得改**：`YYYY-MM-DD HH:MM:SS | HEX数据`（不加毫秒、不加序号，Q-12 裁定）。P13 的失败行是唯一的例外，且仅在 M5 诊断期。
8. **只读不写**：固件里**不得出现任何**合闸 / 分闸 / 锁扣 / 解锁 / 复位 / 写寄存器 / 广播帧。本阶段唯一的请求帧就是下面这几条读帧。
9. **不引入第三方库**；帧仍是手写组装。
10. **`secrets.h` 编译期守卫保留**，不得削弱。
11. **只提交自己负责的文件**（上一轮的教训：同仓库有 WorkBuddy 在途改动）。
12. **🔴 运行期唯一可观察通道 = UDP**（现场无 USB 转 485，且真机带电时 USB 必须拔掉）。
    ⇒ **P13 是强制项，不是可选项。** 没有它，这次首跑一旦不通就是"盲飞"：既没有串口日志，
    也没有任何失败原因，只能得出"不通"这一个结论。

## 二、改动清单

### 2.1 `01_firmware/esp32c3_gateway/config.h`

| # | 项 | 改法 |
| --- | --- | --- |
| C1 | `RS485_CHAR_TIMEOUT_MS` | **`25` → `8`**。这是 M4 期间为"电脑端从站经 USB 转 485 批量交付"临时放大的档位，**M5 起收回正式值域 4~8，取上界 8**（真机是纯硬件 UART，不存在 USB 批量交付抖动）。同时把该行注释里"⚠️【临时档位·2026-10-04 M4 重测专用】"改为"M5 正式档位（4~8，取 8）"，并保留"若真机出现半帧则进一步收紧"的提示 |
| C2 | `MODBUS_TEST_FRAME` / `MODBUS_TEST_FRAME_LEN` | **保留**，但注释里明确：**仅供 `RS485_MODE_LOOPBACK_SELFTEST = 1` 的串口层自检使用；真实总线模式（=0）下不得再发 `0x03`** |
| C3 | 新增 `QI_READ_SPLIT_3SEG` | **编译期宏，默认 `1`（开）**。`1` = 3 段读取（M5 默认）；`0` = 一帧读全（仅用于验 E-02 的 A 分支） |
| C4 | 新增 3 段请求帧 | `QI_SEG1_FRAME {0x01,0x04,0x00,0x00,0x00,0x10,0xF1,0xC6}`<br>`QI_SEG2_FRAME {0x01,0x04,0x00,0x10,0x00,0x10,0xF0,0x03}`<br>`QI_SEG3_FRAME {0x01,0x04,0x00,0x20,0x00,0x07,0xB0,0x02}`<br>三段长度均为 **8**（定义 `QI_SEG_FRAME_LEN 8`）。**以上 CRC 已由 `06_tests/m5_frame_check.py` 独立复核，逐字节照抄，不得重算后替换** |
| C5 | 新增"一帧读全"请求帧 | `QI_FULL_FRAME {0x01,0x04,0x00,0x00,0x00,0x27,0xB0,0x10}`，长度 8。供 `QI_READ_SPLIT_3SEG = 0` 时使用 |
| C6 | 新增段期望响应长 | `QI_SEG1_RESP_LEN 37` / `QI_SEG2_RESP_LEN 37` / `QI_SEG3_RESP_LEN 19` / `QI_FULL_RESP_LEN 83`。⚠️ **仅作长帧兜底的初值**，实际收帧仍必须走"按 byte count 动态算"，不得写死判帧长（见 2.2 P4） |
| C7 | 新增合并缓冲上限 | `QI_MERGED_LEN 78`（39 个寄存器 × 2 字节），并在注释里写明拼接偏移：S1→0、S2→32、S3→64 |
| C8 | `MODBUS_RX_BUF_MAX` | **保持 96**（最大一帧 83 字节，已够），不动 |
| C9 | 文件头"⚠️【待确认·阻塞】实物 485 模块主芯片型号未定" | 该阻塞**已闭环**（实物丝印确认 MAX13487，见 `00_context.md` 五 待确认盲区）。建议把这段注释措辞改为"已确认 MAX13487"，**只改注释、不改代码** |

### 2.2 `01_firmware/esp32c3_gateway/esp32c3_gateway.ino`

| # | 项 | 改法 |
| --- | --- | --- |
| P1 | 段索引 | 新增 `static uint8_t g_segIndex = 0;`（0/1/2）。**一轮 = 依次跑完 S1、S2、S3 三段**，不是"每秒读一段" |
| P2 | `ST_TX` 选帧 | 按 `g_segIndex` 选择当前段的请求帧（`QI_READ_SPLIT_3SEG = 0` 时固定用 `QI_FULL_FRAME`）。`g_txFrame` 长度随之变化，`MODBUS_TX_LEN` 需改为运行期变量或按段求值 |
| P3 | 段序号自增 | 一段收完（无论成功 / 失败）后 `g_segIndex` 前进；走完 S3 后回到 0，并标记"本轮结束" |
| P4 | 帧长驱动 | **保持现有的"按 `byte count` 动态算"逻辑**（`need = rxFrame[2] + 5`，仅在功能码确认为 `0x03`/`0x04` 时才把 `byte[2]` 当字节数）。它对 37/19/83 自动成立，**不要新增"按段写死 37/19"的判定**；`g_expectRxLen` 只在 `QI_READ_SPLIT_3SEG = 0` 时用作 83 的初值 |
| P5 | 拼接 | 新增 `static uint8_t g_merged[QI_MERGED_LEN];`。每段校验通过后，把**数据域**（去掉地址 1 + 功能码 1 + 字节数 1 + CRC 2）拷到 `g_merged` 的偏移 0 / 32 / 64 |
| P6 | 失败降级 | **每段必须独立校验**（地址、功能码、CRC）。**任一段失败即整轮失败** —— 本轮不得上传完整数据、不得用部分段拼出"看起来正常"的数据。失败原因必须记下来供 P13 使用 |
| P7 | 连续失败计数 | 某段连续失败 `N = 3` 次时，本轮整体丢弃并打印 **`[M5] PARTIAL/FAIL`**（含段号与失败原因），**不上传残缺数据**。该段一旦成功，计数清零 |
| P8 | 上传时机 | **只有 S1+S2+S3 三段全部成功**，才在 `ST_SEND` 把 `g_merged`（78 字节）HEX 化，与时间戳拼成 `时间戳 \| HEX数据` 后 UDP 上行 |
| P9 | 周期基准 | `g_nextPollMs += POLL_INTERVAL_MS` 仍在**一轮三段全部结束**后执行 ⇒ **整体仍是 1 秒一轮**，不是每段 1 秒。注意三段合计耗时约 `3 × (8.3ms 发送 + 38.5ms 接收)` ≈ 140ms，远小于 1s，不会挤掉节奏 |
| P10 | 日志（**必做，操作卡 §6 第 8 条**） | 每条解析日志必须能看出**当前帧类型（`0x04`）与当前段号（`S1`/`S2`/`S3`，或 `FULL`）**。建议在现有行尾追加 `SEG=S1` 之类字段 |
| P11 | 日志前缀 | **保留 `[M4]` 前缀不要改成 `[M5]`** —— `06_tests/` 下的 `m4_verify.py` / `serial_capture.py` 等判定脚本按 `[M4] 解析 OK` / `[M4] CRC 失败` / `[M4] 帧长异常` 行做统计，改前缀会让它们全部失配。**若总控认为必须改成 `[M5]`，请同时列出需要同步修改的脚本清单** |
| P12 | 只输出原始值 | 固件**只输出 78 字节原始寄存器值**，**不做任何工程量换算**（电压 / 电流 / 温度 / 电量的 ×0.01、−40、÷1000 等一律留给 PC 侧）。理由：Q-08 主判据是"原始寄存器值完全相等"，固件里加换算等于把未验证的公式固化进代码 |
| **P13** | **每轮一行 UDP（🔴 强制项，见硬约束 12）** | 每一轮（**不论成败**）都必须在 `ST_SEND` 发**恰好一行** UDP，作为本次首跑唯一可观察通道：<br>· **三段全成功** → `时间戳 \| <78 字节 HEX>`（与 Q-12 一致，39 个寄存器）<br>· **任一失败** → `时间戳 \| FAIL:<段号>:<原因>`，例如 `FAIL:S2:TIMEOUT`、`FAIL:S3:CRC`、`FAIL:S1:EXC84-02`<br>· `<原因>` 取值**限定这六种**，便于电脑侧 `udp_listen.py` 直接判读：`TIMEOUT` / `CRC` / `LEN` / `EXC84-xx` / `ADDR` / `FUNC`<br>· M4 的 `HEARTBEAT` 行**由本行取代**，不再单独发心跳<br>⚠️ 这一条**偏离 Q-12 的纯数据格式**，属 M5 诊断期临时增强，**M5 通过后须回到纯数据格式**。若总控认为不可接受，请给出替代的可观察方案（例如把失败段号与原因编进 HEX 尾部并保持定长） |

## 五、本步之后的现场顺序（2026-10-05 19:08 按现场实际改）

**现场事实（用户确认）**：有充电宝 ✅ / **没有 USB 转 485** ❌ / **真机与 MAX13487 的 A/B 已接好，配电箱带电运行**。

由此产生两条硬性影响：

1. **线 A「台面预演」做不了** —— 它要求把 485 另一头换成 USB 转 485。⇒ **本次跳过线 A，直接上真机**。
   代价：无法用台面实验把"代码问题"与"真机问题"分开，**只能靠 P13 的 UDP 反馈来判读**。
   （`06_tests/m5_slave_04.py` 本步用不上，留待日后回归或有 USB 转 485 时补做。）
2. **运行期没有串口** —— 真机带电时 USB 必须拔掉。⇒ **P13 是唯一依靠**。

**唯一安全的执行顺序**（插 USB 的时刻必须落在「真机断电」窗口内）：

| 步 | 动作 | 真机侧 | 谁做 |
| --- | --- | --- | --- |
| 0 | 电脑 `ipconfig /all` 确认 WLAN IP 是否仍为 `192.168.1.114`；**不一致就先改 `UDP_TARGET_IP` 并并入同一次烧录**（断电窗口只有一次，不能烧两遍） | — | 你 |
| 1 | **给配电箱断电**（若为三相须断全三相；有条件就验电） | **断电** | 老师 / 电工 |
| 2 | 插 ESP32 USB → 烧录 → 确认成功（`Writing at 0x...` / `Hash of data verified.`） | 断电 ⇒ **安全** | 你 |
| 3 | **拔掉 USB** → 接充电宝给 ESP32 供电 | 断电 | 你 |
| 4 | 电脑侧起 `python 06_tests/udp_listen.py 8888 300` | 断电 | 你 |
| 5 | **合闸** | **带电** | 老师 |
| 6 | 给 ESP32 上电（充电宝）；电脑侧逐秒读 UDP，跑 ≥60 s 并保存记录 | 带电（**USB 全程不插**） | 你 |

**要看串口日志（拿 `解析 OK / CRC 失败 / 帧长异常` 统计项）时**：回到第 1 步（**再断一次电**）→ 插 USB 抓
`python 06_tests/serial_capture.py COM5 115200 60` → 看完拔 USB → 回第 3 步。

> ⚠️ **A/B 已接在真机上，所以「真机带电」期间绝不允许插 USB。** 这是本次唯一不能协商的一条。
> ⚠️ 每次插 USB 前都要**重新确认**配电箱处于断电状态 —— 不要凭"刚才断过"就认为现在没电。
> ⚠️ 想省掉"每次看日志都要断电"的代价 ⇒ 买一个 **RS485 隔离模块**或 **USB 隔离器**（几十元）。
