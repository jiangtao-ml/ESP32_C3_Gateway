## 1. 项目名称

ESP32-C3 替换树莓派网关项目

## 2. 项目目标

### 2.1 项目背景

现有架构使用树莓派（成本 500-800 元）作为中间数据采集网关，节点数量多，导致整体成本过高。

### 2.2 项目目标

使用 ESP32-C3 SuperMini（约 50 元）+ MAX13487 RS-485 模块替换现有树莓派网关，重写架构，当前目标是先在面包板上跑通原型机。

核心动机是降成本：树莓派约 500-800 元，ESP32-C3 SuperMini 约 50 元。

系统数据流：

1. 底层设备：QI 用电数据采集设备（约 300 元），支持 RS-485 通信，Modbus RTU 协议。
2. 中间网关：ESP32-C3 SuperMini + MAX13487 485 模块，负责轮询采集、加时间戳、UDP 上传。
3. 上层接收：电脑上的“网络调试助手”通过 UDP 协议接收数据 —— **现为 JSON**（数据行 + 心跳行，功能对齐批次 1 起）；M5 之前曾是「时间戳 + HEX 数据」。

## 6. 关键硬件与安全约束

### 6.1 硬件清单

- 主控：ESP32-C3 SuperMini，3.3V 逻辑，使用 HardwareSerial(1)，RX=GPIO20，TX=GPIO21（主控板 PCB 型号 HW-466AB）
- 扩展底板：HW566 V0.0.1 扩展板（提供 5V、3.3V、锂电池供电接口）。面包板原型阶段（阶段三）暂不使用；直接由电脑 USB 给 ESP32-C3 供电，由 SuperMini 的 5V 引脚给 MAX13487 供电。HW566 留到阶段四/五上锂电池时再启用。
- 通信模块：RS-485 模块（主芯片型号待丝印复核，见下条）。若为 `MAX13487` / `MAX13488`：+5V 供电、AutoDirection 自动方向控制、无需 DE/RE 控制引脚（EN 固定高电平）；若为 `MAX485` / `MAX3485`：EN 即方向控制脚，须由 GPIO 动态切换（固件已内建 `RS485_DE_PIN`，默认 `-1` 不启用）。
- ✅ **实物 485 模块主芯片型号（2026-10-04 闭环）**：用户读实物 8 脚芯片丝印确认为 **`MAX13487`**（与口述、老师说法一致）。因此：+5V 供电、AutoDirection 自动方向控制、**EN 接固定高电平**、固件 `RS485_DE_PIN` 保持 `-1`。三合一款页面渲染图（`MAX485 ESA`）不代表实物，此前的阻塞项解除。
- ⚠️⚠️ **【2026-10-04 M4 实测确认·最容易踩的坑】模块丝印 `TXD` / `RXD` 是「交叉」约定**：
  模块丝印写的是**模块自身的收发方向** —— 模块 `TXD` = 芯片 `RO`（**接收输出**）、模块 `RXD` = 芯片 `DI`（**发送输入**）。
  **正确接法：`GPIO21`（ESP32 TX）→ 模块 `RXD`；`GPIO20`（ESP32 RX）← 模块 `TXD`。**
  按"同名对接"（`GPIO21`→模块 `TXD`）会**双向全断**（`GPIO21` 顶在芯片输出脚对撞、`DI` 从未被驱动），**而模块电源灯仍亮**，极易误判为硬件故障 —— 本项即 M4 卡 5 天的真凶，详见 `02_docs/14_M4排障全过程复盘_2026-10-04.md`。
- 另注：**总线侧 3 脚丝印顺序为 `B` / `A` / `GND`**（`GND` 在最后），旧材料记作 `GND / A / B` 是错的。
- EN 引脚（丝印已确认为 `MAX13487`）：接**固定高电平**（模块 VCC/5V），不得悬空 / 接 GND / 动态切换（悬空若对应 SHDN# 会关断器件）。详见 `04_ai_prompts/00_context.md` 三.5。固件侧 `RS485_DE_PIN` 保持 `-1` 不启用。
- EN 引脚（⚠️ 接法随实物芯片型号二选一，先读丝印）：① `MAX13487` / `MAX13488`（5V 双向，芯片无 DE 脚）→ 接**固定高电平**（模块 VCC/5V），不得悬空 / 接 GND / 动态切换（悬空若对应 SHDN# 会关断器件）；② `MAX485` / `MAX3485`（单向，EN 即方向控制脚）→ EN 必须接 GPIO 由固件切换，**严禁固定接高**。详见 `04_ai_prompts/00_context.md` 三.5。固件侧：MAX485 / MAX3485 接法只需把 `01_firmware/esp32c3_gateway/config.h` 的 `RS485_DE_PIN` 改成实际 GPIO 号即启用（默认 `-1` = 不启用）。

### 6.2 ⚠️ 安全约束（必须遵守）

1. ⚠️ 共地：ESP32、485 模块（MAX13487 或 MAX485 / MAX3485）、USB 转 485 模块、电源，所有 GND 必须连在一起。
2. ⚠️ 电平转换（口径与 `04_ai_prompts/00_context.md` 三.2 一致）：485 模块的 RXO（= 模块 `TXD` 脚）空闲电平必须先万用表实测（Q-10）。① 实测为 5V → 必须 1kΩ 接 RXO、2kΩ 接 GND，交点接 GPIO20（约 3.33V）；严禁 2k 接 RXO、1k 接 GND（仅 1.67V，ESP32 无法识别高电平）。② 实测为 3.3V → 直连 GPIO20，**不要分压**（分压后约 2.2V，低于 ESP32-C3 的 VIH ≈ 2.475V）。
   > ✅ **【2026-10-04 实测】本模块拆除 1k/2k 分压、`RXO` 直连 GPIO20 后，M4 仍 100% 通过**（连续 65 秒解析 OK 65 次）⇒ 该模块**可直连**，与老师"不用电阻"一致。⚠️ 但**未用万用表实测其空闲电平**，电气合规性仍属 `[待确认]`；M5 接真机前建议补测。
3. 供电：`MAX13487` 接 5V，ESP32-C3 接 3.3V（丝印已确认为 `MAX13487`）。
4. 总线：模块照片核验板载 `472 / 121 / 472`（4.7kΩ / 120Ω / 4.7kΩ），即**偏置 + 终端在板上存在**（视觉证据充分，万用表终判仍属 `[待确认]`）。
