## 3. 上报 JSON —— 从二进制里读出的格式串原文

### 3.1 数据行（由 3 段字符串拼接而成）

```
{"seq":%lu,"mac":"%s","ip":"%s","ts":"%s","ts_ok":%s,
 "openState":"%04X","record1":"%04X","record2":"%04X","record3":"%04X",
 "frequent":%.1f,"leakage_current":%.3f,"N_temp":%d,

 "<A|B|C>_temp":%d,"<A|B|C>_voltage":%u,"<A|B|C>_current":%.2f,"<A|B|C>_Pf":%.2f,
 "<A|B|C>_power":%u,"<A|B|C>_Q":%u,"<A|B|C>_S":%u,"<A|B|C>_H":%u,"<A|B|C>_L":%.3f,   ← 三相共用一段模板（%c）

 "power":%u,"Q":%u,"S":%u,"H":%u,"L":%.3f}
```

### 3.2 心跳行（独立一类）

```
{"seq":%lu,"mac":"%s","ip":"%s","ts":"%s","ts_ok":%s,"type":"hb","rssi":%d,"free_heap":%u,
 "poll_ok":%u,"poll_err":%u,"udp_tx":%u,"queue":%u,"dropped":%u,"cfg":"%s"}
```

### 3.3 `/status`

22 项，与用户截图**逐字一致**（`mac/fw/configured/wifi_ssid_cfg/wifi_from_builtin/chrony/server/
port/poll_period_s/wifi_connected/ssid/ip/rssi/ap/ap_ip/time_synced/uptime_ms/poll_ok/poll_err/udp_tx/queue/dropped`）。

### 3.4 由此确认的 5 件事

| # | 结论 | 依据 |
| --- | --- | --- |
| 1 | **39 个字段的顺序与寄存器 0..38 完全一致** | 格式串顺序 = `openState, record1-3, frequent, leakage_current, N_temp, A_*, B_*, C_*, power, Q, S, H, L` ⇒ 与 `05_hardware/STB3-125_Database_Fields.md` 的字段表、与我们的寄存器映射**三方独立吻合**（这是铁证） |
| 2 | **`openState` 确实在**，格式 `"%04X"` | ⇒ 我上一轮"截图里没看到 openState，是不是漏了"是**我看漏/截图截断**，**不是遗漏**。问老师的这条可以撤掉 |
| 3 | **`record1/2/3` 名字就是 `record1`**（不是 `recor1`），且为 `"%04X"` **十六进制字符串** | ⇒ 我的**半字节解码得到确认**（4 位十六进制 = 4 条分闸原因） |
| 4 | **固件输出的是"工程量"**（`frequent:%.1f`、`leakage_current:%.3f`、`L:%.3f`） | ⇒ 与我们的"只搬原始值"是**两条路线**，取舍见 `02_docs/16` §8.2 |
| 5 | **这个版本没有 `dev` 字段**，用的是 **`mac`**（完整 MAC） | 格式串里 `"dev"` 0 命中 |

## 4. ⚠️ 最重要的一条：**老师那边至少有两个版本在跑**

| 对比项 | 截图那台（MAC `3C:0F:02:AF:49:E4`） | 我读的这块板（MAC `48:F6:EE:15:9B:88`） |
| --- | --- | --- |
| `dev` 字段 | **有**（`"dev":"ESP485-AF49E4"`） | **无**，用 `mac` |
| `quality` 字段 | **有**（`"quality":"00"`） | **无**（全镜像 **0** 命中） |
| `openState` | 截图里未见（疑截断） | **有** |
| 配置页第 ④ 栏管理账号 | 截图里未见（只有 ①②③） | **有** `admin_user` / `admin_pass` |
| `/status` 22 项 | 一致 | 一致 |

⇒ **两台设备字段不一致。** ⇒ **对接前必须先锁定"以哪个版本为准"**，否则我们的入库表结构会反复改。
⇒ 这条必须进"问老师"清单，而且要一并问**版本号**与**能否给源码**。

## 6. 其它技术事实

| 项 | 值 | 影响 |
| --- | --- | --- |
| 运行时 | **arduino-esp32 2.x**（`esp-idf: v4.4.7` + `Arduino Event Malloc Failed!`） | ⚠️ **我们用 3.3.10-cn（IDF 5.x）** ⇒ 若要复用他的代码，**core 版本不同、API 有差异** |
| OTA | **支持**（`esp_ota_get_running_partition`、`OTA verification failed! Start rollback to the previous version`） | 双分区 + 失败回滚；`02_docs/16` §5-P1 建议的 OTA 他已做 |
| 配置存储 | **NVS**（`nvs_flash_init_partition`、`ESP_ERR_NVS_*`） | 不是 SPIFFS；掉电不丢 |
| 出厂默认 | UDP 接收 **`172.16.0.2:9000`** | 与我们的 NTP 主源同机（实验室那台） |
| 串口日志前缀 | `[DEV ]` / `[CFG ]` / `[BOOT]` | 可据此写解析脚本 |
| 状态指示 | 有 `[LED` 字样 | 有板载状态灯 |
| 心跳机制 | 独立 `"type":"hb"` 行 | 线上数据与心跳**分成两类行** |

## 7. 对我们要做的事的影响

| # | 结论 |
| --- | --- |
| 1 | **对齐目标要从"格式"升级为"版本"** —— 先问清以哪版为准，再谈字段 |
| 2 | **`seq` + 心跳计数器机制直接借鉴**：`poll_ok/poll_err/udp_tx/queue/dropped` 他都有了；我们 P13 目前只差"**累计计数器**"这一项 |

| 4 | **安全建议要收敛**（他的鉴权已做）。真正还开着的口子只剩三条：<br>① **AP 常开**（页面自述"始终在线"）⇒ 建议 **超时关闭 / 按键开启**，不牺牲装机便利<br>② **`/status` 未登录即可读**（暴露 MAC、内网 IP、上游地址）⇒ 建议与配置页同权限<br>③ **UDP 明文无认证** ⇒ 长期换 MQTT + TLS |

## 8. 方法与边界（可复用）

**流程**（已固化，工具 `06_tests/fw_strings.py` 可复用）：

1. `esptool -p <port> get-security-info` —— **先看 `Flash Encryption`**；开了就只能找作者要源码
2. `esptool -p <port> flash-id` —— 确认 flash 容量
3. 读 **app 区**（Arduino 默认在 `0x10000`，镜像头以 `E9` 开头）—— **别读整片 4 MB**：
   实测整片读会在 ~0x42000 附近 `Packet content transfer stopped` 中断，且慢。
   改成 **128 KB 分块**读，失败块再拆成 **8 KB 子块**重试（实测该 flash 在 `0x30000–0x50000`
   一带对整块读不友好，拆到 8 KB 就基本能过）。
4. `python 06_tests/fw_strings.py <app.bin>` —— 分类报告（格式/字段、配置/配网、Web/HTTP、
   错误/质量、固件信息、JSON 键名、HTML 片段）
5. `--raw` 导出全部字符串；`--grep <kw>` 定向查找

**边界**：只读、不改板子；只能拿字符串；若作者开启 Flash 加密则此路不通。
