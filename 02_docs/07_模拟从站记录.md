## 2. 测试环境与链路方案

**方案：真实 485 总线**（非 UART 短接回环）

```
ESP32 UART1 ──MAX13487──▶ A/B 总线 ──▶ USB 转 485 ──▶ 电脑（Modbus 从站模拟器）
```

| 要素 | 内容 |
| --- | --- |
| 主控 | ESP32-C3 SuperMini（主控板 PCB 型号 HW-466AB），`Serial1` = UART1，RX=GPIO20 / TX=GPIO21 |
| 485 收发 | MAX13487（+5V，AutoDirection，无 DE/RE 控制引脚） |
| 电脑侧 | USB 转 485 模块（**本期为旧模块：仅 A/B 端子，无 GND**） |
| 从站工具 | **Modbus Slave**（Witte Software，modbustools.com）—— 用户已选定（由用户 2026-10-03 确认）；备选 `pymodbus`。用法见 `01_firmware/esp32c3_gateway/README.md` |
| 从站参数 | 地址 1、9600、8N1、无校验 |

## 3. 故障现象

- ESP32 串口**持续**输出 `[M4] 超时`，超时参数为 **首字节 80ms / 字符间隔 4ms / 兜底 300ms**。
- 链路始终表现为 **`RX=0`（期望 9 字节）**，即**从站方向完全没有回包**。
- 超时参数本身**落在任务书 §6.1.2 规定区间内**（50-100ms / 3-5ms / 300ms），**不构成故障原因**。

**现象归类**：属"**接收通路无数据**"，可能来源为 ① 从站未响应、② 总线物理层不通、③ 接收侧（MAX13487 → GPIO20）通路异常、④ 电脑侧收发模块失效。

## 4. 排查过程与结论

### 4.1 排查方法：隔离法 + 自环测试

目的：把 ESP32 从链路中摘出，**单独验证电脑侧 USB 转 485 模块自身的收发通路**，从而把"模块故障"与"固件/接线故障"分离。

步骤：

1. 断开 ESP32。
2. 仅保留旧 USB 转 485 模块插在电脑上（该模块**只有 A/B 端子、无 GND 端子**）。
3. **短接该模块的 A/B 线**，构成自环（发送 `abc`）。
4. 观察接收区。

### 4.2 观察结果

- **接收区一片空白**，未回显 `abc`。

### 4.3 结论

| 项 | 内容 |
| --- | --- |
| **主结论** | ~~**旧 USB 转 485 模块物理损坏**~~ |
| **⚠️ 2026-10-04 更正** | **该判定已推翻，须复验。** 其所依据的「A/B 短接自环」是本项目的**方法学错误**——两线半双工 485 短接 A/B 后 `V_AB ≡ 0`，接收器落入 ±200mV **不定区**，**健康模块同样不回显**，故该测试无判别力。详见 `02_docs/13_M4排障记录_2026-10-04.md` §2（含 MaxLinear / Renesas / Industrial Monitor Direct 三处权威依据）。 |
| 判定依据 | 隔离状态下、不依赖 ESP32 与 MAX13487 的纯自环测试即无回显，故障域被限定在"电脑 + USB 转 485 模块"这一环 |

**推测的损坏原因**（未做破坏性验证，标注为**推测**）：

| 推测原因 | 机理描述 | 可信度 |
| --- | --- | --- |
| 前期 **TX-TX 短路**导致大电流 | 两个发送端对接时，输出驱动器可能互相灌电流，超出器件承受范围 | 推测 |
| **强电共地引入电势差** | 现场存在强电环境；模块无 GND 端子，地电位浮动差可能击穿收发芯片 | 推测 |

### 4.4 结论的置信度与残余不确定性（**待新模块到货后排除**）

| 编号 | 残余不确定性 | 排除方法 |
| --- | --- | --- |
| U-1 | 自环空白也可能由**串口驱动未安装/异常、COM 口选错、串口助手参数不匹配**导致（本次未单独记录 COM 口与驱动状态） | 新模块到货后用**同一自环法**复测，与本次结果对照 |
| U-2 | **GPIO20 可能已受损**：本次接线**未加分压**（见 §5.2），5V 直入已超其绝对最大额定 3.6V。若新模块到货后仍为 `RX=0`，应优先怀疑 GPIO20 输入通路 | 做 GPIO20 输入通路验证 / 换脚对照（**先排除此项，再怀疑新模块**） |

> 重要性：U-2 会让"打坏引脚"伪装成"模块又坏了"，从而显著延长排障时间，**必须在新模块到货后的第一轮就排除**。

## 5. ⚠️ 安全隐患与违规记录

### 5.1 共地缺陷（环境性隐患）

| 项 | 内容 |
| --- | --- |
| 事实 | 旧 USB 转 485 模块**只有 A/B 端子、无 GND 端子** |
| 后果 | ESP32、MAX13487 与电脑之间**无法建立统一的 0V 参考点**，易形成**地环路电流**，轻则误码、重则烧毁模块 |
| 定性 | **违背** `MEMORY.md` 硬件安全红线**第 1 条**「所有 GND 共地（含 USB 转 485）」；同时违背 `README.md` §6.2 安全约束第 1 条 |
| 处置 | ✅ **已闭环（2026-10-04）**：带 GND 端子的 CH340 模块已到货并投入使用；**旧模块（黑，FTDI）经双端口背靠背互测证明收发完全正常（双向 5/5）** —— 此前"物理损坏"判定**已推翻**。⚠️ 旧模块的真实缺陷只有"缺 GND 端子"（真机上仍建议更换）。 |

### 5.2 未按文档要求做分压（**明确违规操作**）

| 项 | 内容 |
| --- | --- |
| 事实 | 实际接线中**未给 ESP32 GPIO20 加 1kΩ / 2kΩ 分压电阻**，RXO 侧信号未经降压直接进入 GPIO20 |
| 定性 | **严重违反** `MEMORY.md` 硬件安全红线**第 2 条**，以及 `README.md` §6.2 安全约束第 2 条 |
| 规定接法 | `RXO —[1kΩ]— 分压节点 —[2kΩ]— GND；分压节点接 GPIO20`；**严禁只串 1kΩ 直连** |
| 风险 | GPIO20 绝对最大额定 = VDD+0.3V = **3.6V**；直连 5V 可能**永久损坏引脚** |
| **与本次故障的关系** | **不是**本次 `RX=0` 的直接原因（故障已定位到 USB 转 485 模块侧），但属**独立的高危违规**，必须单独立项整改；**不得因"这次不是它引起的"而忽略** |
| 保护 GPIO20 的必要性（重申） | GPIO20 既是本项目唯一的 485 接收入口，又是 ESP32-C3 的 UART0 默认引脚；一旦损坏，需换脚改接并同步修改固件与文档，代价远高于一颗 1kΩ + 一颗 2kΩ 电阻 |

### 5.3 强电 / 弱电直连风险（老师现场额外警告）

老师在群内特别提醒：

> 「采数据时要用**充电宝供电，不要用电脑**」
> 「**MAX13487 是 5V 双向的，不要切换 EN 引脚**」

| 项 | 内容 |
| --- | --- |
| 风险机理 | 后续接入 **220V 强电环境的 QI 真机**时，若电脑与现场共地，将经 USB 形成**强电—弱电通路**，**极易烧毁电脑主板** |
| 对策方向 | 接入真机前**必须**引入 **RS485 隔离模块**，或**断开电脑供电**（改用充电宝/独立电源） |
| 与既有口径的关系 | **⚠️ 口径已于 2026-10-03 更正（见 §5.4）**：「不要切换 EN 引脚」的真实含义是「**EN 要接固定电平，不要当作方向脚来回切换**」，而**不是**"保持断开"。原「EN 未确认前保持断开」口径**已作废** |
| 落地时点 | **M5（接入 QI 真机）开始前必须闭环**，不得带入 M5 |

### 5.4 EN 引脚口径更正（2026-10-03）—— **撤回「保持断开」**

> **⚠️ 历史记录（写于实物芯片型号核实前）**：本节结论建立在「本模块为 MAX13487 / MAX13488」的前提上。购买页为**三合一款**（`MAX3485` / `MAX485` / `MAX13487`）、页面渲染图丝印为 **`MAX485 ESA`**，**实物 8 脚芯片型号待丝印复核**；**现行口径一律以 `04_ai_prompts/00_context.md` 三.5 为准（条件式，先读丝印）**。若实物为 `MAX485 / MAX3485`，本节「EN 接固定高电平」的结论**不适用**（须改为 GPIO 动态切换方向）。

**触发**：老师指出"做不出来正是因为 EN 断开"。复核后**老师是对的**，本项目此前口径有误。

**原口径的立论前提**：EN 可能是 `DE`（驱动使能）；若为 DE 而接高，驱动器会**长期使能、占死总线**。因此"不接"被视为最保守选项。该前提同时来自 Codex 技术审查（`02_docs/02_任务书技术审查_Codex.md` 第 9 点 / H-1）。

**新证据（MAX13487E 官方数据手册 8 脚 SO）**：

```
1 RO    2 RE#    3 SHDN#    4 DI    5 GND    6 A    7 B    8 VCC
```

**该芯片根本不存在 `DE` 引脚** → 原立论前提不成立。模块丝印「EN」的真实候选只剩 `RE#` 与 `SHDN#`。

**重新判定**：

| 模块丝印 EN 实际是 | 悬空 | 接固定高电平 |
| --- | --- | --- |
| `RE#`（低有效接收使能；数据手册：拉高即交由 AutoDirection 控制接收器） | 芯片内部**热插拔上拉**会把它拉高 → AutoDirection 正常接管 ✓ | ✓ 同样正确 |
| `SHDN#`（低电平关断；数据手册：拉高才正常工作） | 悬空可能被拉低 → **器件进入关断，A/B 无任何差分输出** ❌ | 正常工作 ✓ |

→ **接高在两种诠释下都正确；悬空只在 `RE#` 情形下安全。**

**本记录（历史）曾写成**：EN 接固定高电平（首选 VCC/5V，3.3V 亦可）。**⚠️ 该结论已随实物型号复核要求二次更正为条件式** —— 以 `04_ai_prompts/00_context.md` 三.5 为准：`MAX13487 / MAX13488` → 接固定高电平；`MAX485 / MAX3485` → 必须由 GPIO 动态切换方向，**严禁固定接高**。**丝印未读前不得给 EN 接任何电平。**

**对本轮 `RX=0` 的意义（重要）**：

- 若 EN 实为 `SHDN#` 且此前悬空 → **MAX13487 处于关断态**，与实测的"完全无回包、`RX=0`"**完全吻合**。
- 因此 `RX=0` 很可能是**双重原因**：① USB 转 485 模块损坏（已确认）；② MAX13487 被 EN 关断（待验证）。**两项都必须修，缺一不可** —— 只换模块而不处理 EN 仍会失败。
- 也解释了**为什么 M3 通过而 M4 不通**：M3 的 `GPIO21 → GPIO20` 短接回环**绕过了 MAX13487**，EN 问题不会暴露。**"M3 回环通过"不等于"485 通路已验证"。**
