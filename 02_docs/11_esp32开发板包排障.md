## 1. 当前状态与排查方向

### 1.1 当前状态（最小上下文）

- Arduino IDE 已安装。
- 开发板包**未安装成功**。
- 卡在 **`esp-x32@2601`**。
- 电脑**可上网**。
- **COM 口未查询**。

补充说明（供判定参考）：

- `esp-x32` 是 esp32 平台下的 **Xtensa 工具链**（交叉编译器）工具依赖，命名格式为 `esp-x32@<版本标签>`，在日志中通常显示为 `esp32:esp-x32@<版本标签>`。社区实测日志中可见同类写法（如 `esp32:esp-x32@2302`）`[待确认]` 本项目 `2601` 对应的确切版本。
- 该包**体积大**（工具链级别，通常上百 MB 量级），是整条安装链上**最容易卡住/超时**的一环；卡在这里**不代表** IDE 或驱动有问题。
- 当前状态**尚未排除**：下载源（海外）不可达、校园网对相关域限速或拦截、单包超时过短、半成品残留。**尚未开始**：COM 口查询（属 M1 另一项，见任务书 §7.3）。

### 1.2 方向 A：镜像源配置

**目标**：把开发板管理器索引从海外源切到 **官方 CN 镜像**，从源头改善连通性。

**步骤**：

1. Arduino IDE → 文件 → 首选项（Preferences）→ **附加开发板管理器网址**。
2. 填入官方文档给出的 CN 镜像地址（**稳定版**）：
   `https://jihulab.com/esp-mirror/espressif/arduino-esp32/-/raw/gh-pages/package_esp32_index_cn.json`
   - 开发版（如需）：同路径末段改为 `package_esp32_dev_index_cn.json`
   - 官方源（海外线路通畅时）：`https://espressif.github.io/arduino-esp32/package_esp32_index.json`
   - 以上三条地址均出自 Espressif 官方 Troubleshooting 文档（见下方「来源」），**不要使用来路不明的第三方镜像**。
3. **点击「OK」保存**（该输入框不点 OK 不生效）。
4. 工具 → 开发板 → 开发板管理器 → 搜索 `esp32` → 选择 Espressif Systems 提供的版本，**国内网络请选带 `-cn` 后缀的版本**。

**关键注意**：

- 官方文档明确：CN 镜像版本**不支持自动更新**，后续升级需回到管理器手动选择更高的 `-cn` 版本。
- 需要多个网址时用**英文逗号**分隔，不要换行。
- 若管理器**列表为空 / 搜不到 esp32**，几乎总是第 2 步的 URL 写错或第 3 步没保存。

**判定**：开发板管理器能拉出 `esp32 by Espressif Systems`，且版本下拉中能看到 `-cn` 条目 → 方向 A 生效。

**来源**：Espressif 官方文档《Troubleshooting → Installing → Slow or unstable downloads》（`docs.espressif.com/projects/arduino-esp32/en/latest/troubleshooting.html`）。

### 1.3 方向 B：网络 / DNS / 代理排查

**目标**：区分「源不可达」「被限速」「超时过短」三种不同病因，对症处理。

**步骤**：

1. **先记录现象**：是进度长时间 0%，还是报超时类错误？把**报错原文**抄下来（判定表见 §2）。
2. **换网络（优先做）**：改用**手机 2.4GHz 热点**下载。项目已确认该退路可用（见任务书 §4.2.1）；校园网常对 GitHub / 镜像站限速或拦截，换热点是最快的一次性排除法。
3. **DNS 排查**：`nslookup jihulab.com`、`nslookup espressif.github.io`，看是否解析。不通则换公共 DNS（例：`223.5.5.5`、`119.29.29.29`，**以本机实测为准** `[待确认]`）。
4. **代理排查**：Arduino IDE 2.x 走系统代理。确认系统代理 / PAC 是否处于「开着但不通」的状态；必要时临时关闭或改为直连再试。
5. **加长超时（可选）**：Arduino IDE 2.x 底层为 arduino-cli，可在用户配置 `C:\Users\<用户名>\.arduinoIDE\arduino-cli.yaml` 末尾追加：
   ```yaml
   network:
     connection_timeout: 900s
   ```
   `[待确认]` 本机 arduino-cli.yaml 的确切路径与该版本是否支持该键（以本机实际生成的文件为准，不要新建文件）。

**判定**：下载进度能持续推进到 100%，不再长时间停顿。

### 1.4 方向 C：手动离线安装

**目标**：绕开 IDE 的下载器，用「先下归档 → 丢进缓存目录 → 让 IDE 复用」的方式补齐 `esp-x32`。

**原理**：IDE 把下载中的包放在 `staging\packages`；该目录中的归档会被识别并直接使用，**不再重新下载**。

**步骤**：

1. **完全退出 Arduino IDE**（确认任务管理器里无残留进程）。
2. 打开平台索引 JSON（即方向 A 中填的那个 URL），在 `toolsDependencies` 中找到 `esp-x32` 对应的 `version` 与 `url`——**下载地址以索引 JSON 中的定义为准**，不要凭包名拼接。
3. 用浏览器或支持**断点续传**的下载工具把该归档下到本地（校园网环境建议配续传）。
4. 把归档放入：`C:\Users\<用户名>\AppData\Local\Arduino15\staging\packages\`
   - **文件名必须与索引中的定义一致**，否则不会被识别。
5. 重新打开 IDE → 再次点击安装 → IDE 会识别本地已有归档，只补齐剩余部分。

**关键注意**：**不要在原窗口反复点「安装」**；每次重试前都先退出 IDE。

**判定**：`C:\Users\<用户名>\AppData\Local\Arduino15\packages\esp32\` 下出现**完整**的目录结构，且「工具 → 开发板」菜单出现 ESP32 系列选项 → 方向 C 成功。

`[待确认]`：`esp-x32@2601` 对应归档的确切文件名与 URL（以平台索引 JSON 为准）。

### 1.5 方向 D：PlatformIO 备选方案

**适用时机**：方向 A / B / C 均反复失败，或需要把工具链版本固定下来。

**做法要点**：

- 在 VS Code 中安装 PlatformIO 扩展，平台选择 `espressif32`。
- **注意**：PlatformIO 仍要下载**同一套工具链**，不解决"网络不通"根因；它的优势是**重试与缓存更友好**，且可用 `platformio.ini` 固定版本，便于与文档、Codex 对齐。
- **代价（重要）**：工具链路径与 Arduino IDE 不同；工程组织方式也不同（`platformio.ini` + `src/`，与当前 `01_firmware/esp32c3_gateway/` 的 `.ino` 结构不一致）→ 会引入新的工程组织方式，**必须经总控批准后才可切换**，不得自行改动 `01_firmware/`。

**判定**：能完成一次**真实编译**（不是"扩展装好"就算成功）。

`[待确认]`：本项目 ESP32-C3 SuperMini（主控板 PCB 型号 HW-466AB）在 PlatformIO 下的推荐 board id（社区常用 `esp32-c3-devkitm-1`，**需按实物核对**）。

### 1.6 执行顺序与判定路由

| 顺序 | 动作 | 成功判据 | 失败则 |
| --- | --- | --- | --- |
| 1 | **A** 配 CN 镜像 + 选 `-cn` 版本 | 管理器拉到 `esp32 by Espressif Systems`（含 `-cn` 条目） | → 2 |
| 2 | **B** 换手机热点 / 查 DNS / 查代理 / 加长超时 | 进度持续推进至 100% | → 3 |
| 3 | **C** 手动离线补齐 `esp-x32` 归档 | `Arduino15\packages\esp32\` 完整 + 板菜单出现 ESP32 | → 4 |
| 4 | **D** 切换 PlatformIO（**须总控批准**） | 一次真实编译通过 | 上报总控，重新评估路线 |

**铁律**：**一次只做一个方向**；每换一个方向前**彻底退出 IDE**（避免半成品与文件锁）；每一步**记录现象与报错原文**，失败也要留证据（本工程约定：结论写文档，日志放 `03_logs/`）。

## 2. 附：常见现象与判定表

| 现象 | 最可能病因 | 先做 |
| --- | --- | --- |
| 进度长时间 0%（> 10 分钟不动） | 源为海外 / 网络被限速或拦截 | A → B |
| 报超时类错误（如 `DEADLINE_EXCEEDED` / `Client.Timeout`） | 单包过大 + 超时过短 | B（加长超时）→ C |
| 管理器搜不到 `esp32` / 列表为空 | URL 未保存或写错 | A（重新保存并核对字符） |
| 安装"看起来完成"但板菜单里没有 ESP32 | 工具链不完整（正是卡在 `esp-x32` 的结果） | C |
| 每次重试都卡在同一个包 | `staging` 中半成品残留 | 清理后再走 C |
| 换热点后一次通过 | 校园网侧限制（非本机问题） | 记录结论，后续大包下载均走热点 |

## 3. 附：清理与续传目录（**谨慎操作**）

Windows 下 Arduino IDE 的用户目录（系统级，**不在本工程内**）：

```
C:\Users\<用户名>\AppData\Local\Arduino15\
├─ staging\packages\    下载缓存 / 断点续传目录
└─ packages\esp32\      已安装的平台与工具链
```

**纪律**：

1. **只清 `staging\packages\`**（缓存，可安全清空）；`packages\esp32\` 只有在确认要"卸载重装"时才动。
2. **先完全退出 IDE** 再操作，否则文件被占用。
3. 该目录属**系统级用户目录**，动手前先记录原始内容清单；如需删除，优先手动删除而非脚本批量删除。
4. 任何清理动作都要在本文档回写"清了什么、结果如何"。
