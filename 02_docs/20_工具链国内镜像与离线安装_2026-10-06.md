## 0. 一句话

**`-cn` = Espressif 官方中国镜像的版本标记**（与官方版本号一一对应，如 `3.3.10-cn` ↔ 官方 `3.3.10`）；它的下载走**乐鑫 CN CDN `dl.espressif.cn`**。
**根因是 `github.com` 在国内直连不通**（本机实测超时 / 0 字节）。⇒ 只要把包分成两类走两条通道（见 §4），**PlatformIO 迁到 3.x 完全可以不下 GitHub**。

---

## 1. `-cn` 是什么（已用本机数据确认）

本机 `Arduino15` 下同时存在两个索引，对照即得结论：

| 索引文件 | 版本列表（节选） | 所有下载 URL 的域名 |
| --- | --- | --- |
| `package_esp32_index_cn.json`（**CN 镜像**） | `3.3.10-cn, 3.3.9-cn, …, 2.0.17-cn, …`（**全部带 `-cn`**） | **`dl.espressif.cn`（50/50 平台 + 1041/1041 工具）** |
| `package_esp32_index.json`（官方） | `3.3.12, 3.3.11, 3.3.10, 3.3.9, …`（**无后缀**） | `github.com`（52/52 平台） |

**结论（三条）**：
1. **`-cn` 只是"发布渠道标记"，不是不同的代码分支** —— `3.3.10-cn` 对应官方 `3.3.10`，**同一版本、不同镜像**。
2. **CN 索引把全部下载 URL 换成了 `dl.espressif.cn`** —— 这就是"国内镜像"的实质。
3. **CN 镜像索引来源**：`https://jihulab.com/esp-mirror/espressif/arduino-esp32/raw/gh-pages/package_esp32_index_cn.json`（**极狐 GitLab**，Espressif 官方 CN 镜像仓）。本机 `~/.arduinoIDE/arduino-cli.yaml` 的 `board_manager.additional_urls` 已配置此地址 ✅。

⚠️ **一个必须知道的取舍**：CN 镜像**会滞后** —— 官方已到 `3.3.12`，CN 最高 `3.3.10-cn`。
⇒ 对"固定版本、可复现"其实**有利**（钉一个 CN 版本即可）；但**不要以为它总是最新**。

## 4. ⭐ 两条通道的**规则**（本文件最有用的部分）

实测归纳出两条可复用的替换规则：

### 规则 A —— **Espressif 官方组织**的 GitHub 资产 ⇒ 走乐鑫 CN CDN
```
github.com/espressif/<repo>/releases/download/...      ← 原始
      ↓  替换
dl.espressif.cn/github_assets/espressif/<repo>/releases/download/...   ← 可直连、快
```
已多例实测通过（`espressif/crosstool-NG`、`espressif/arduino-esp32`、`espressif/esp32-arduino-lib-builder`）。

### 规则 B —— **非 Espressif 组织**（如 `pioarduino/*`）⇒ 走 GitHub 代理
```
https://gh-proxy.com/https://github.com/<org>/<repo>/releases/download/...   （或 ghfast.top 同法）
```

📌 **关键发现（决定了 3.x 迁移能不能离线做）**：`pioarduino/registry` 里那些看着像"工具链包"的 zip，**其实只是清单桩**。
例：`riscv32-esp-elf-14.2.0_20241119.zip` 只有 **1644 字节**，解压后是 `package.json` + `tools.json`。
而 `tools.json` 里给出的**真实工具链地址指向 `github.com/espressif/crosstool-NG`** ⇒ **规则 A 适用，可走 CN CDN**。
⇒ **所以 3.x 迁移所需的大包，绝大多数都能走 `dl.espressif.cn`，不必碰 GitHub。**

## 6. 落地步骤（复用既有脚本，不重造）

1. **拿到平台**：经规则 B 下载 `platform-espressif32-55.03.30.zip`，解压到 `~/.platformio/platforms/espressif32/`（或让 PlatformIO 用本地 zip）。
2. **扩展 `06_tests/pio_cn_seed.py` 的 `TARGETS`**：把 §5 表里走**规则 A** 的包加进去（framework @3.3.0 / -libs / riscv32 工具链），URLPattern = `dl.espressif.cn/github_assets/...`。
   - 该脚本已有的能力正好对口：**下载 → 拍平多余顶层目录 → 写 `package.json`/`.piopm`**（解决"乐鑫原版包缺 PlatformIO 清单"的历史坑）。
3. **走规则 B 的包**（平台本体、espidf、各桩包）用 gh-proxy 前缀拉取。
4. **pip 依赖**改清华源：`pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple`（或 `PIP_INDEX_URL` 环境变量）。
5. **跑 `pio run` 验证**：能完成一次**真实编译**才算成功（不是"平台装上"就算）。
6. **做对照验证**（`02_docs/19` §3.2 第 4 条）：与 `arduino-cli` (3.3.10-cn) 产物比对 + 一次台面 + 一次真机。
7. **自持归档**：把 §5 的包 zip 存进项目发布物 / 内网，日后**发布构建不依赖任何外网**。

### 备选（最快，0 下载）
**让老师打包他机器上 `~/.platformio/{platforms,packages}` 直接拷过来** —— 若老师的组内环境已是 pioarduino 3.x，这一步 5 分钟搞定，比任何镜像都快。

## 8. 3.x 落地结果（2026-10-07 实测，已编译成功）

### 8.1 实际落地版本（风险表 #2 闭环）

实际装的是 **`pioarduino/platform-espressif32@55.03.311` = Arduino `3.3.11` / IDF `5.5.5`**，不是 §5 调研时的 55.03.30（3.3.0）。
原因：**pioarduino 跳过了 3.3.10**（tag 序列 `55.03.39`=3.3.9 → `55.03.311`=3.3.11 → `55.03.312`=3.3.12），
故取与板子 3.3.10 **最接近的 3.3.11**；±1 个 patch 的差异由迁移后对照验证覆盖（`02_docs/19` §3.2）。

### 8.2 首次真实编译结果 ✅

`pio run -d 01_firmware/pio_verify` ⇒ **`[SUCCESS] Took 117.17 seconds`**（日志 `03_logs/pio3_m.log`）：

| 指标 | PlatformIO (3.3.11) | Arduino IDE 基线 (3.3.10-cn) | 差 |
| --- | --- | --- | --- |
| RAM | **39 384 B**（12.0% / 327 680） | 39 284 B | **+100 B** |
| Flash | **1 019 703 B**（77.8% / 1 310 720） | 1 004 899 B | **+14 804 B（+1.5%）** |

产物：`firmware.bin` 1 042 912 B · `firmware.elf` · `firmware.factory.bin` · `bootloader.bin` · `partitions.bin`（均在 `01_firmware/pio_verify/.pio/build/esp32c3/`）。
⚠️ 差异在合理预期内（core 差 1 个 patch + 构建系统不同），但**行为等价性未证** ⇒ 仍需 `02_docs/19` §3.2 的台面/真机对照。

### 8.3 `pio_cn_seed.py` v2.0 要点

平台驱动（读 `platform.json` 自动列包）· 桩包解析（读 `tools.json` 取 win64 真实地址）· magic-byte 判格式（sha1 缓存文件无扩展名）· `park()` 改名代替 `shutil.rmtree`（沙箱拦批量删除）· 双通道 `rewrite()`（规则 A/B）· 成功阈值 `MIN_OK=128`（桩包仅 ~1 KB）。

### 8.4 首编路上踩过的 6 个环境坑（重装/换机 playbook）

1. **`MSYSTEM`**：Git Bash 会注入 `MSYSTEM=MINGW64` ⇒ `idf_tools.py` 直接拒绝运行（"MSys/Mingw is not supported"），`unset` 无效（沙箱重注入）。⇒ **必须在 PowerShell 里跑 `pio`**（`Remove-Item Env:MSYSTEM` 保险）。
2. **uv 不认 `PIP_INDEX_URL`**（认 `UV_INDEX_URL`）；且 **esptool 5.x 在 PyPI 只有 sdist 无 wheel** ⇒ uv 编译 sdist 时的批量清理被沙箱拦截。⇒ **预先用 pip 把 16 个 pioarduino 依赖装进 `~/.platformio/penv`**（pip 走 `https://pypi.org/simple`；清华源缺 `pioarduino>=6.1.19`）。
3. **uv `--force-reinstall` 中途超时会拆坏 penv**（先卸后装，卸载完被掐 ⇒ dist-info 缺 `METADATA`）⇒ `pip install --ignore-installed --no-deps <pkg>` 修复（跳过卸载步骤）。
4. **esptool 的 MATCH 守卫**：`penv_setup.py::install_esptool` 先查 `import esptool` 的路径是否指向 `tool-esptoolpy` 包目录，MATCH 才跳过 uv 强装。⇒ **`pip install -e tool-esptoolpy --no-deps --no-build-isolation`**（penv 需先有 setuptools/wheel）+ 补 `bitstring/cryptography/pyserial/reedsolo/PyYAML/intelhex/rich_click<2/click` 8 依赖；**`click` 钉 `<8.4`**（pioarduino 6.2.0 要求 `click<8.4,>=8.0.4`，与 esptool 的 `click<9` 取交集）。
5. **`.piopm.spec.uri` 必须与 `platform.json` 的 URL 版 spec 完全一致**（`test_pkg_spec` 对 URL spec 按 uri 判等）⇒ 不一致时 pio 认为"未安装" ⇒ 触发重装 ⇒ 删除旧包目录（数千文件）被沙箱拦截。**已对 5 个已装包批量对齐 uri**。
6. **`lib_ldf_mode` 禁止带 `+`**（上游 espressif/arduino-esp32#9782：3.x 网络层重构与宏预处理求值冲突 ⇒ WiFi 报 `Network.h` 找不到）；而纯 `deep` 模式下 **LDF 不会跟进 `src/` 之外的 .ino 扫描库依赖**（依赖图为空）⇒ **`src/main.cpp` 显式 `#include <WiFi.h>` 作 LDF 锚点**（include guard 下与 .ino 重复包含无害）。

> 备注：`pio3_m.log` 尾部 `SystemExit: 1 / safe-delete` 噪音是 **SCons atexit 清理临时 .rsp 文件被沙箱拦截**，发生在 `[SUCCESS]` **之后**，对产物无影响。
