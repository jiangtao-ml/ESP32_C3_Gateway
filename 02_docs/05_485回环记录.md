## 1. 目标与验收标准

| 项 | 内容 |
| --- | --- |
| 目标 | **先不接 MAX13487**，证明「串口能自发自收」，为 M4 的真实总线收发打底 |
| 做法 | `GPIO21`（TX1）与 `GPIO20`（RX1）用杜邦线短接；固件置 `RS485_MODE_LOOPBACK_SELFTEST = 1` |
| 验收 | 每秒一行 `[485] 回环 OK TX=8 RX=8`，帧内容与 `01 03 00 00 00 02 C4 0B` 完全一致；连续 1 分钟无 FAIL / TIMEOUT |

## 2. 接线与前置

| 项 | 内容 |
| --- | --- |
| 短接 | `GPIO21` ↔ `GPIO20`（SuperMini 上 USB-C **对侧那一排的末端两个脚**，先认丝印） |
| ⚠️ 必须断开 | **MAX13487 不接** —— 避免总线偏置 / 终端电阻干扰判断，也避免 5V 电平灌进 GPIO20 |
| 固件开关 | `config.h` 的 `RS485_MODE_LOOPBACK_SELFTEST = 1`（期望收回同一 8 字节）；**测完务必改回 `0`** |
| 编译选项 | `USB CDC On Boot = Enabled`（否则 `Serial` 占 GPIO20/21 与 `Serial1` 抢脚） |

## 4. 关键修正（M3 暴露的时序问题）

### 4.1 清 RX 缓冲必须挪到 `write()` **之前**

- 半双工 485 / 回环下，"自己发的字节会先进 RX 缓冲"。
- ❌ 原设计（任务书 §4.3 / §6.1.2 原文）：`write()` → `flush()` → 清 RX ⇒ **回环会丢首字节**。
- ✅ 修正为：**清 RX → `write()` → `flush()`**。
- 该修正已同步到任务书 v0.3.4、`00_context.md` 与固件实现。**这是本项目的关键正确性修正之一。**

## 5. ⚠️ 重要边界：M3 通过 ≠ 485 通路已验证

> **M3 的回环是 `GPIO21 → GPIO20` 的直连短接，它 100% 绕过了 MAX13487。**

因此 **M3 通过时看不出来的问题**包括：

- 模块 `EN` 悬空导致器件关断；
- 模块 `RXO` 未分压 / 电平不匹配；
- 模块 `TXD`/`RXD` 接反（**后来 M4 卡 5 天的真凶**）；
- A/B 接线、共地、模块供电。

👉 **M3 只能证明「ESP32 的 UART1 + 两个 GPIO + 烧录链路」是好的**，不能替代 M4。

## 6. 失败判读（速查）

| 现象 | 优先怀疑 |
| --- | --- |
| `TIMEOUT ... RX=0` | 短接线未插好 / 插错引脚 / `USB CDC On Boot` 不是 Enabled |
| `TIMEOUT ... RX=N`（0<N<8） | 半帧 —— 杜邦线接触不良；或 MAX13487 仍挂在总线上 |
| `FAIL ... 期望 … 收到 …` | 后面紧跟的 `[差异] byte[i]` 会指出具体错位字节 |
