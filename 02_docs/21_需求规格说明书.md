## 0. 怎么读这份文档（三条硬约定）

1. **本文件描述「代码实际实现了什么」，不描述「文档希望实现什么」。** 两者不一致的地方**不在正文里调和**，一律进 §9 差异清单，逐条给出「以谁为准」。
2. **每条需求必须能定位到代码行。** 定位不到的，要么不存在，要么进 §11 缺口清单。
3. **未经实测的一律标 `[待验证]`。** 本文件不生产数字，只生产可验证的陈述。

> 与任务书的关系：任务书是**意图**（我们要做什么），本文件是**基线**（我们实际做成了什么）。验收时两份都要看——只看任务书会验收不存在的东西，只看代码会丢掉需求初衷。

## 1. 目的、范围与术语

### 1.1 目的

- 为 M7 验收提供**可追溯的需求基线**：任何一条验收判据，都能回答「它对应哪条需求、哪行代码、哪次测试」。
- 把散落在注释、排障记录、对话里的**隐性约束显性化**（§8），避免换人接手后踩同一个坑。
- 暴露**代码与文档的偏差**（§9），这是本文件最有价值的部分——偏差不记录，就会在答辩时变成"你们说的和做的不一样"。

### 1.2 范围

**在范围内**：ESP32-C3 网关固件的全部已实现行为、对上游电表的接口、对下游接收端的接口、资源配置与运行约束。

**不在范围内**：PC 侧接收程序的实现（属 `22_实现与交付方案.md` 第二章）、PCB 设计、商业化路径、电表内部实现。

### 1.3 术语

| 术语 | 含义 |
| --- | --- |
| QI / STB3-125 | 用电数据采集设备（电表），RS-485 / Modbus RTU，地址 1 |
| 网关 | ESP32-C3 SuperMini + MAX13487 模块构成的采集网关 |
| 数据行 | 一轮采集成功后上行的 JSON 行，**无 `type` 字段** |
| 心跳行 | 每轮必发的 JSON 行，`type:"hb"` |
| 失败行 | 采集失败时额外发的 JSON 行，`type:"err"` |
| 轮 / 行 | 一轮 = 一次 1s 调度周期；一行 = 一个 UDP 报文。正常轮 2 行（心跳 + 数据），失败轮 2 行（心跳 + err） |
| epoch | 设备一次开机到下次重启之间的连续运行段。重启后 `seq` 与计数器归零 |
| raw | 78 字节寄存器原值的 HEX 表示（39 × 2B），上行数据行携带 |

## 2. 系统上下文

### 2.1 部署拓扑

```
┌──────────────┐   RS-485 (2 线 + GND)   ┌─────────────────────┐   WiFi 2.4G    ┌──────────────┐
│  STB3-125    │◄───────────────────────►│  ESP32-C3 SuperMini │───────────────►│  PC (接收端)  │
│  电表 / 地址1 │  9600 8N1 Modbus RTU    │  + MAX13487 (5V)    │  UDP 单播      │  :8888       │
│  只读        │  FC=0x04 读输入寄存器    │  FW 0.6.0-batch3    │  本地口:12345  │  [待实现]     │
└──────────────┘                         └─────────────────────┘                └──────────────┘
                                                  │
                                          常驻 SoftAP: ESP485-<MAC6> @192.168.4.1
                                          配置页 / /status  / /save / /reset
```

### 2.2 三方边界与职责

| 角色 | 负责 | **不负责（明确不做）** |
| --- | --- | --- |
| 电表 STB3-125 | 提供 39 个输入寄存器（30001–30039） | 不做时间戳、不做重传、不做加密 |
| 网关固件 | 轮询、组帧、CRC、解析、打时间戳、组 JSON、UDP 发送、本地配置 | **不做工程量二次加工**（见 §9 D-07）、不做补传队列（§11 G-02）、不做加密（§11 G-03） |
| 接收端 | 收包、解析、落库、统计、出报告 | 不控制设备（无下行指令通道） |

### 2.3 系统边界：只读铁律

网关对电表**只发 `0x04` 读输入寄存器**，共 1 条业务请求帧（一帧读全）与 3 条降级帧。**严禁**任何写寄存器、合闸、分闸、锁扣、复位、广播。这条不是实现细节，是验收前置条件：

> 任务书 §9.2 第 5 条：验收动作**不得包含** STB3-125 控制类命令。

代码侧证据：`config.h` L121-122 明确 `0x03` 仅用于回环自检、真实总线唯一功能码为 `0x04`；`config.h` L127 的 `0x03` 帧仅在 `RS485_MODE_LOOPBACK_SELFTEST=1` 分支使用。

## 3. 功能需求

> 编号沿用任务书 FR-01~09 以保持追溯连续；FR-10 起为本文件新增（代码已实现但任务书未编号）。

### 3.1 网络与时间

| 编号 | 需求 | 实现要点与代码位置 | 验收方法 |
| --- | --- | --- | --- |
| FR-01 | WiFi STA 联网 | `WiFi.mode(WIFI_AP_STA)`（`.ino` L1251）；静态 IP `192.168.1.200`（`config.h` L27-30）；凭据来自 NVS 或 `secrets.h` | 上电后 ping 通；`/status` 的 `wifi_connected=true` |
| FR-02 | NTP 三源对时 | 主 `172.16.0.2` → 备 `ntp.aliyun.com` → 备 `203.107.6.88`（`config.h` L43-48）；TZ `"CST-8"`（L52，**不可加尖括号**）；仅 WiFi 连通后触发（`.ino` L493-501）；未同步每 60s 重试（`config.h` L60） | `ts_ok=true` 且 `ts` 与 PC 时间差 ≤1s |
| FR-03 | 时间戳两态 | 已对时 → `YYYY-MM-DDTHH:MM:SS`；未对时 → `BOOT+<秒>`、`ts_ok=false`（`.ino` L438-446） | 人为断网后观察 `ts_ok` 变 false、`ts` 变 `BOOT+` |

**FR-02 的关键实现约束（易被"优化"掉）**：「已同步」的唯一判据是**本轮会话收到过 NTP 回包**（`sntp_getreachability()!=0`，`.ino` L425-430），**不是** `getLocalTime()` 返回值。原因：ESP32 复位后 RTC 可能残留旧值，`getLocalTime()` 会拿旧值骗过判定，产出"看着正确、实际偏差几小时"的时间戳。

### 3.2 总线与采集

| 编号 | 需求 | 实现要点与代码位置 | 验收方法 |
| --- | --- | --- | --- |
| FR-04 | Modbus RTU 收发 | 9600/8N1/无校验，从站 1；手写帧（不用第三方库）；**发送前清 RX**（半双工自发自收）；发送完成判据 = `Serial1.flush()`（`.ino` L1051-1227 状态机内） | 回环模式下 8 字节原样收回 |
| FR-05 | 三级超时 + 帧长驱动收帧 | 首字节 80ms、字符间隔 8ms、整帧兜底 300ms（`config.h` L88-95）；收满 `byteCount+5` 立即结束，不等超时（`.ino` L949-957） | 正常轮无超时；人为拔线后 300ms 内返回失败 |
| FR-06 | 1 秒非阻塞循环 | `millis()` 调度（`config.h` L57）；全工程无 `delay()` 业务等待 | 心跳到达间隔 ≈1s |
| FR-07 | 单状态机 | `IDLE→TX→WAIT_RX→PARSE→SEND`（`.ino` L71-77）；所有等待以 deadline 表达 | 代码审查；无阻塞点 |
| FR-08 | CRC16/Modbus 校验 | 多项式 `0xA001`、初值 `0xFFFF`、**低字节先**；不通过则记 `reason=CRC` | 注入错 CRC 帧，确认被拒 |

### 3.3 上行与上报（FR-09~12）

| 编号 | 需求 | 实现要点与代码位置 | 验收方法 |
| --- | --- | --- | --- |
| FR-09 | WiFi 最小自恢复 | `setAutoReconnect(true)` + `setSleep(false)` + `persistent(true)`（`.ino` L1265-1267）；`wifiTick()` 每 5s 检查、重连节流 ≥5s（`config.h` L58-59） | 关闭 AP 再打开，≤60s 恢复 |
| FR-10 | **JSON 数据行** | 仅本轮成功才发；携带 39 项工程量 + `raw`(233 字符) + `quality`/`invalid`/`seg`（`.ino` L694-720）；典型 892 B，最坏 1106 B（`config.h` L191-195 缓冲 1200） | 抓包核对字段完整性；`raw` 解析回 39 寄存器与字段值自洽 |
| FR-11 | **心跳行** | 每轮必发（含失败轮），`type:"hb"`；含 `rssi`/`free_heap`/`mode`/`poll_ok`/`poll_err`/`udp_tx`（`.ino` L737-745） | 每轮可见；计数器单调递增 |
| FR-12 | **失败行** | `QI_SEND_ERR_ROW=1` 且本轮失败才发，`type:"err"`；`seg` ∈ {F,S1,S2,S3}，`reason` ∈ {TIMEOUT,CRC,ADDR,FUNC,LEN,EXC84-XX}（`.ino` L760-766） | 拔总线后可见 err 行且 reason 合理 |

**FR-11 的两处语义陷阱（接收端必须知道）**：

- `poll_ok` / `poll_err` 是**开机以来累计值**，不是增量；比较两个心跳要相减。
- `queue` / `dropped` **恒为 0**，是占位字段（`.ino` L745 注释：补传队列属 M6 未实现）。**不得**把它们当作"补传队列正常"的证据——目前根本没有补传队列（§11 G-02）。

| 编号 | 需求 | 实现要点与代码位置 | 验收方法 |
| --- | --- | --- | --- |
| FR-13 | 运行时自适应读取模式 | 启动默认**一帧读全** `01 04 00 00 00 27 B0 10`（`config.h` L154），期望 83 B；**仅当本会话从未成功且连续失败 ≥3 轮**才降级 3 段（`config.h` L165，`.ino` L1197-1203）；降级后**本会话不回切**；曾成功过则**永不降级** | 模拟从站拒绝 39 寄存器读 → 观察 `mode` 从 `full` 变 `3seg` |

## 4. 接口需求

### 4.1 IF-01 · UDP 数据行（下游核心契约）

- 方向：网关 `192.168.1.200:12345` → PC `<ip>:8888`
- 编码：UTF-8 JSON，单行，无换行符
- **无 `type` 字段**——接收端必须靠"有 `raw` 且有 `quality`"判型

| 分组 | 字段 | 类型/格式 | 说明 |
| --- | --- | --- | --- |
| 标识 | `seq` | uint32 十进制 | 全局行序号，三类行共享 |
| | `dev` | `ESP485-` + MAC 后 6 位 HEX 大写 | 设备唯一标识 |
| | `mac` | `AA:BB:CC:DD:EE:FF` | **仅数据行有** |
| | `ip` | 点分十进制 | STA 本地 IP |
| 时间 | `ts` | ISO8601 或无 `T` 的 `BOOT+<秒>` | 秒级，无毫秒（Q-12 裁定） |
| | `ts_ok` | `true`/`false` | **时间可信度的唯一判据** |
| 状态量 | `openState` | 4 位 HEX 字符串，如 `"00F0"` | |
| | `record1`/`record2`/`record3` | 4 位 HEX 字符串 | 分闸记录，半字节语义见 DR-04 |
| 全局量 | `frequent` | 1 位小数 | Hz |
| | `leakage_current` | 3 位小数 | A |
| | `N_temp` | 整数 | ℃ |
| 分相量 ×3 | `A/B/C_temp` | 整数 | ℃，恒 −40 语义见 DR-03 |
| | `A/B/C_voltage` | 无符号整数 | V |
| | `A/B/C_current` | 2 位小数 | A |
| | `A/B/C_Pf` | 2 位小数 | 0–1 |
| | `A/B/C_power` / `_Q` / `_S` | 无符号整数 | W / var / VA |
| | `A/B/C_H` | 无符号整数 | 电量高字 |
| | `A/B/C_L` | 3 位小数 | 电量低字（度） |
| 总量 | `power`/`Q`/`S`/`H`/`L` | 同上 | 总有功/无功/视在/电量 |
| 质量 | `quality` | `"OK"` / `"PARTIAL"` | |
| | `invalid` | 逗号分隔字段名，可为 `""` | 最多 12 个候选 |
| | `seg` | `"1"`（一帧读全）/ `"3"`（三段） | **与 err 行的 `seg` 语义不同**，见 §9 D-06 |
| 原始 | `raw` | 78 字节 → 大写 HEX，空格分隔，**233 字符** | 可完整重放 |

**字段计数**：39 项测量量 = 4 状态/记录 + 3 全局 + 27 分相 + 5 总量，与 39 个寄存器一一对应。

### 4.2 IF-02 · 心跳行

13 个键：`seq` / `dev` / `ts` / `ts_ok` / `type:"hb"` / `rssi` / `free_heap` / `mode`（`"full"`\|`"3seg"`）/ `poll_ok` / `poll_err` / `udp_tx` / `queue`(恒0) / `dropped`(恒0)。

**不含** `mac` / `ip` / `quality` / `raw`。

### 4.3 IF-03 · 失败行

8 个键：`seq` / `dev` / `ts` / `ts_ok` / `type:"err"` / `seg` / `reason` / `poll_err`。
`seg` ∈ {`F`, `S1`, `S2`, `S3`}，`reason` ∈ 6 种。

## 5. 数据需求

### 5.1 DR-01 · 寄存器映射
39 个输入寄存器 `30001–30039`（0-based `0x0000–0x0026`）与 39 个字段**同序一一对应**。以 `05_hardware/STB3-125_字段字典.csv` 为唯一事实来源。

### 5.2 DR-02 · 量程与精度

| 字段 | 量程 | 换算 |
| --- | --- | --- |
| `frequent` | 0–100 Hz | raw × 0.1 |
| `leakage_current` | 0–1 A | raw ÷ 1000 |
| `*_temp` | −40–160 ℃ | raw − 40 |
| `*_voltage` | 0–600 V | 1:1 |
| `*_current` | 0–655.35 A | raw ÷ 100（恒合法，不判越界） |
| `*_Pf` | 0–1 | raw × 0.01 |

### 5.3 DR-03 · `-40 ℃` 伪装语义
该型号 `A/B/C_temp` 寄存器恒为 0 → 换算后恰好等于量程下限 −40。`QI_PHASE_TEMP_ABSENT=1`（默认）时视为"型号已知不上报"：**不进 `invalid`、不降 `quality`**。真正越界（<−40 或 >160）才进 `invalid`。

> 这是"数据缺失伪装成合法值"的典型陷阱。接收端必须知道：**看到 −40 不是故障，也不是有效测量**。

### 5.4 DR-04 · `record1..3` 半字节
分闸记录，按 4 位 HEX 逐半字节解读。`0` 与 `F` 的语义差异 `[待确认]`（`PROGRESS.md` §8.1）。

### 5.5 DR-05 · 电量公式（存疑）
固件使用 `H × 65536 / 1000 + L`（`.ino` L685）。另有一解相差 1000 倍，`[待确认]`。**本项未闭环前，电量类指标不得进验收结论。**

### 5.6 DR-06 · `raw` 是复算载体
数据行同时携带工程量与 `raw`。这产生一个强校验能力：接收端可用 `raw` 独立重算 39 字段，与 JSON 里的工程量比对，**自动发现固件换算 bug**。这是"固件只搬运原始值"设计原则的落地价值，必须作为验收项（见 `22` §5.6）。

## 7. 约束与假设

### 7.1 硬件红线（8 条，来自 `PROGRESS.md` §7 与 `00_context.md` 三）

1. 所有 GND 共地（ESP32、MAX13487、USB 转 485、电源）。
2. MAX13487 接 5V，ESP32 接 3.3V，同时上电。
3. 485 按**字母**接线不按位置：总线侧 `B` → `A` → `GND`（GND 在最后）。
4. **`TXD`/`RXD` 是交叉约定**：`GPIO21`→模块 `RXD`；`GPIO20`←模块 `TXD`。同名对接会双向全断而电源灯仍亮（M4 五天根因）。
5. **EN 接固定高电平**（MAX13487 无 DE 脚），不悬空、不接 GND、不动态切换；`RS485_DE_PIN = -1`。
6. `RXO` 空闲电平 **5V 需 1k/2k 分压、3.3V 直连**；本项目实测可直连，但万用表实测**始终未做**，电气合规性 `[待确认]`。
7. **电表只读**。
8. 真机在带电配电箱内：开箱前断电 + 验电；真机运行时拔 USB（否则经 USB 地与 485 共模烧主板）。

### 7.2 假设（未验证，验收时需标注）

- A-01：环境 WiFi 2.4G 在 168h 内可用且未被客户端隔离。
- A-02：PC 的 IP 在长跑期间保持不变（**历史上已漂移 3 次，此假设极脆弱**）。
- A-03：`poll_err` 的失败轮原因可用 `reason` 分类覆盖。
- A-04：老师接收端只在明文模式下对接。

## 8. 隐含需求（逆向独有）

这些需求代码里做了、但任何文档都没写过。**去掉它们系统会坏，但没人知道为什么坏**。

| 编号 | 隐含需求 | 代码证据 | 不满足的后果 |
| --- | --- | --- | --- |
| IR-01 | 必须 `Serial.setTxTimeoutMs(0)` | `.ino` L1245 | 无主机读串口（真机拔 USB）时，每轮约 190 次 `write` 阻塞，把 1s 周期拖到 ~19s |
| IR-02 | `millis()` 比较必须写成 `(int32_t)(now-t) >= 0` | `.ino` L243、L1057 等 | 49.7 天回绕后判据反转（168h 内不触发，但换写法就埋雷） |
| IR-03 | 发送前必须清 RX | `.ino` 状态机 TX 分支 | 半双工自发自收，自己发的字节进缓冲，污染应答 |
| IR-04 | 发送完成判据只能用 `Serial1.flush()` | `.ino` TX 分支 | 用固定 `delay()` 在 9600 下不可靠（任务书 §6.1.2 明确） |
| IR-05 | 短帧必须按"帧长 == 本段请求寄存器数"双重校验 | `.ino` L971-978（P0-1） | 从站返回自洽短帧时会静默掺入上一轮残留值（`g_merged` 无清零点） |
| IR-06 | NTP 判据必须用 `sntp_getreachability()` | `.ino` L425-430 | 复位后旧 RTC 骗过 `getLocalTime()`，时间戳偏差数小时 |
| IR-07 | WiFi 重连必须节流 ≥5s | `config.h` L59 | 断网时每秒重连风暴，挤占主循环 |
| IR-08 | 降级必须"只降不升、曾成功则永不降" | `.ino` L1197-1203 | 偶发总线抖动会把设备永久钉在 3 段模式，效率减半 |
| IR-09 | `poll_ok`/`poll_err` 必须在 WiFi 判断**之前**自增 | `.ino` L791-792 vs L798-805 | 断网期间的轮次会从分母里消失，采集率虚高（**这是接收端对账法能成立的前提**） |
| IR-10 | payload 缓冲 1200 B 且必须显式告警截断 | `config.h` L191-195；`.ino` L836 | 静默截断会产出坏 JSON，接收端解析失败 |
| IR-11 | `g_merged` 每段只按偏移覆写、无整体清零 | `.ino` L165 | 任何一段短帧都会残留旧值 ⇒ 必须靠 IR-05 兜住 |
| IR-12 | AP 默认口令必须 MAC 派生（≥8 字符） | `config.h` L227-228 | 短于 8 字符协议栈拒绝启动，设备变砖（需重烧） |
| IR-13 | TZ 必须写 `"CST-8"` 不能写 `"<CST-8>"` | `config.h` L50-52 | 尖括号让偏移量缺省为 0 ⇒ 全部时间差 8 小时 |
