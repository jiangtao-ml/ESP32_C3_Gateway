## 4. 命名约定

### 4.1 目录与文件

| 规则 | 说明 |
| --- | --- |
| `01_` ~ `06_` 前缀**不得改名** | 用于文件管理器固定排序；改了两百多处引用全断 |
| `02_docs/` 用 `NN_名称.md` 递增 | 当前 01~23，**缺 09（成本对比）、10（验收结项）** —— 属 M7 待补交付物，不是遗漏 |
| `04_ai_prompts/` 用 `NN_用途_主题.md` | 00 是上下文，01~07 是施工指令，08 是复核提示词 |
| `03_logs/` 用 `<阶段>_<场景>_<YYYYMMDD>.log` | `real` = 真机数据（证据级）；详见 `03_logs/README.md` §2 |
| 归档区统一叫 `_archive/` | 下划线前缀保证排在最前，且一眼看出不是活跃内容 |

### 4.2 Git 提交

- 格式：`阶段N: 简述`（当前阶段四）
- **只 add 自己改的文件，永不 `git add -A`** —— 会吞掉别人在途的改动
- 事实类改动（参数、帧表、进度）可直接提交；决策类（验收判据、安全红线、接口契约）须同时挂 `PROGRESS.md` §8

## 5. 文件生命周期

| 类别 | 位置 | 可再生 | 可否删 |
| --- | --- | --- | --- |
| 源码 / 文档 / 脚本 | `01/02/04/05/06` | 否（除推理） | 入库后可经 git 恢复 |
| 编译缓存 | `01_firmware/pio_verify/.pio/build/` | 是（重建约 3 min） | 可删，但重建慢，暂留 |
| 构建备份 | `*.bak` | 是 | **已删** |
| Python 缓存 | `__pycache__/` | 是 | **已删** |
| 运行时日志 | `03_logs/` | **否** | **删了不可恢复**，先看 `03_logs/README.md` |
| 本机工具记忆 | `.workbuddy/` | 否 | **禁止删除**（不在 git 内） |
| 凭据 | `secrets.h` | 否 | 禁止入库、禁止张贴 |

## 8. 维护规则（避免再次变乱）

1. **新文档先想清楚归属**：结论 → `02_docs`；过程 → `03_logs`；工具 → `06_tests`；AI 指令 → `04_ai_prompts`。
2. **不新建第 7 个顶层目录**。现有六目录职责已覆盖全部内容类型。
3. **临时产物不要落仓库根目录** —— 写 `.workbuddy/tmp/` 或 `03_logs/`（`.gitignore` 已拦截 `.codex_*` / `*probe.txt`）。
4. **作废 ≠ 删除**：先移 `_archive/` 并在其 README 记一行原因；确认无用再清。
5. **任何目录的「入口文件」只有一个**：根 `README.md` → `PROGRESS.md` → 各目录 `README.md`。层级不重复叙述同一事实，只做指针。
6. **每季度做一次结构体检**：跑一遍 `git status --ignored`，看有没有新的未跟踪大文件或临时产物堆积。
