## 2. 高风险项（需立即决策）

### H-1（最优先）实物 485 模块主芯片型号未定 —— 它决定 EN 能不能接、接什么

- 证据链：商品页是**三合一款**（`MAX3485` 3.3V 单向 / `MAX485` 5V 单向 / `MAX13487` 5V 双向）；页面渲染图芯片丝印清晰可读为 **`MAX485 ESA`**；用户与老师口述为 MAX13487。**页面图不能代表实物，口述也不能替代丝印。**
- 为什么致命：两类芯片的 EN 语义**互斥**—— 
  - `MAX13487 / MAX13488`：芯片本身无 DE 脚，EN 对应 `RE#` / `SHDN#`，**必须固定高电平**，动态切换反而会关断器件；
  - `MAX485 / MAX3485`：EN 就是方向控制脚，**必须由 GPIO 按收发切换**，固定接高会占死总线（自己发的字节被自己收回来，从站永远无法应答）。
- 另外两点随型号变：供电（MAX3485 = 3.3V，其余 = 5V）、RXO 空闲电平（决定要不要 1k/2k 分压）。
- 需要用户做：**用手机微距 / 放大镜拍下模块上 8 脚芯片的丝印**，回复 `MAX13487` 还是 `MAX485`/`MAX3485`。

### H-2 R-13：GPIO20 可能已被 5V 打伤

- 事实：本次 M4 接线**未加分压**，MAX13487 的 RXO（5V 电平）直接进了 GPIO20，而 ESP32-C3 的 IO 绝对最大额定是 **3.6V**。
- 后果：GPIO20 的输入通路可能已经受损，或者“偶发能收、偶发收不到”。这会造成**误判**——把“引脚坏了”当成“模块又坏了”，白买模块、白折腾。
- 处置：新模块（或旧模块复测）到手后，**先做 GPIO20 输入通路验证**再怀疑模块：
  1. 先用 M3 回环模式（`RS485_MODE_LOOPBACK_SELFTEST = 1`，短接 GPIO21↔GPIO20）跑 1 分钟：若回环 100% OK → GPIO20 输入通路基本正常；
  2. 若回环异常（字节缺失 / 恒为 0 / 恒为 1）→ 换用其它可用 GPIO 作 UART1 RX（如 GPIO4 / GPIO5 / GPIO10），同步改 `config.h` 的 `RS485_RX_PIN`、README §6.1、CTX 三节；
  3. 真机上另可用万用表二极管档测 IO 对 VDD/GND 是否击穿（可选）。

### H-3 E-02 / E-03（协议侧）

- E-02：原文写“数据长度不能超过 16”，但“读全部参数”用 `00 27`（39 个）。**只能真机验证**；固件侧 M5 默认走 3 段方案（CRC 已独立复核）。
- E-03：原文把 `01 06 00 0D 00 00 18 09` 标注为“远程锁扣”，按寄存器表它实际写的是 **40014 = 远程分闸**。属**静默高危**：照抄执行会误拉闸。已登记，本阶段**一律禁止执行任何控制类命令**。

## 3. CRC 全量独立复核（回答第 6 条）

- 方法：自写 `CRC16/Modbus`（初值 `0xFFFF`、多项式 `0xA001`、反射/逐位、**低字节在前**），对协议原文、`06_QI协议说明.md`、`05_hardware/STB3-125_Errata.md`、固件 README、`config.h` 中出现过的命令帧逐条重算。
- 结果：**50 条完整帧（26 条命令帧 + §3.4 响应示例帧 + E-02 分段帧 3 条 + E-03 候选帧 4 条等）逐条重算，唯一不通过的是 E-01 一帧**；另 1 条“看似不符”实为**书写口径差异**。（此前写作“33 条通过”，计数与口径均有误，本轮更正。）

| 帧 | 独立计算 CRC | 结论 |
| --- | --- | --- |
| `01 03 00 00 00 02 C4 0B`（回环自测帧） | `0x0BC4` ✓ | 正确 |
| `01 04 00 00 00 27 B0 10`（读全部参数 39 个） | `0x10B0` ✓ | 正确 |
| `01 04 00 09 00 01 E1 C8`（读 A 相电流） | `0xC8E1` ✓ | 正确 |
| `01 04 00 00 00 10 F1 C6`（E-02 S1） | `0xC6F1` ✓ | 正确 |
| `01 04 00 10 00 10 F0 03`（E-02 S2） | `0x03F0` ✓ | 正确 |
| `01 04 00 20 00 07 B0 02`（E-02 S3） | `0x02B0` ✓ | 正确 |
| `01 06 00 0B FF 00 B9 F8`（E-03 锁扣候选） | `0xF8B9` ✓ | 正确 |
| `01 06 00 0B 00 00 F8 08`（E-03 解锁候选） | `0x08F8` ✓ | 正确 |
| `01 06 00 0D FF 00 59 F9`（40014 合闸） | `0xF959` ✓ | 正确 |
| `01 06 00 0D 00 00 18 09`（40014 分闸） | `0x0918` ✓ | **CRC 正确，标注错误**（见 E-03） |
| `01 05 00 02 FF 00 2D FA` | `0xFA2D` ✓ | 正确 |
| `01 01 01 02 90 48`（读线圈回复） | 应为 `0x49D0` → 线上 `D0 49` | ❌ **E-01 原文笔误**，已登记 |
| `01 03 04 00 0A 00 14 DA 3E` | `0x3EDA` ✓ | “`CRC=3EDA`”是**数值写法**，线上字节为 `DA 3E`，不矛盾（已在固件 README 加注） |

**除 E-01 外没有发现新的 CRC 错误**；同时确认全仓库不存在“CRC 抄错却看不出来”的第三处。

## 8. 仍需用户 / 总控确认的清单

1. **【必须】实物 485 模块 8 脚芯片丝印**（`MAX13487` / `MAX13488` / `MAX485` / `MAX3485`）——决定 EN 接法、供电电压、是否启用固件方向控制宏。**丝印未读前不要给 EN 接任何电平。**
2. **【必须】旧模块复测结论**：用 §4.1 自环法复测后，把结果回写 `07_模拟从站记录.md`（“确属损坏”或“其实是接线/引脚问题”）。
3. **【重要】GPIO20 输入通路验证**（H-2 步骤 1~2）——结果决定是否把 UART1 RX 换到其它 GPIO。
4. **【需总控】`RS485_DE_PIN` 选哪个 GPIO**：建议 GPIO3 / 4 / 5 / 10（避开 strapping 脚 2/8/9 与原生 USB 18/19），需与实际接线一致。
5. **【需实测】三级超时微调**：`RS485_CHAR_TIMEOUT_MS` 4ms → 5~6ms 的条件与结果。
6. **【需实测·已升级为功能验收项】** 终端/偏置电阻实际数量（模块到底有几个电阻、120Ω 是否已焊、**A/B 偏置上拉下拉是否存在**）。**手册已明确偏置电阻是 MAX13487 正常工作的必要条件**（见第 9.5 节）——缺了会导致“行为像模块坏了”的假故障，务必在 M3 一并实测。
7. **【需实测】MAX13487 的 RXO 空闲电平**：若实测已是 3.3V，则**不要再分压**（否则高电平被判成低电平）；若为 5V 才用 1k/2k。
8. **【低优先】** `06_QI协议说明.md` §8「第 11 节」引用加括注；`WiFi.persistent` 是否需要为长期运行关掉。
9. **【安全红线】** 任何 STB3-125 控制类命令（含 E-03 候选帧）在 M5 之前**一律不得执行**。

## 9. 数据手册核实（2026-10-03 新增 —— 回应 H-1 的“EN 悬案”）

- **来源**：从 Analog Devices 官网下载 **MAX13487E/MAX13488E 官方数据手册**（19-0740; Rev 3; 2024-08），存入 `05_hardware/MAX13487E_MAX13488E_Datasheet.pdf`（1,540,850 B）。用 `pdftotext` 提取正文逐条核对，非凭记忆。

| # | 核实点 | 手册原文依据 | 结论 |
| --- | --- | --- | --- |
| 9.1 | 8 脚定义、有无 `DE` | Pin Description：`1 RO / 2 RE / 3 SHDN / 4 DI / 5 GND / 6 A / 7 B / 8 VCC`；功能框图内 `DE` 属 **STATE MACHINE** 内部信号 | **全片无 `DE` 引脚**（`RECEIVER_ENABLE` = `DRIVER_ENABLE` 反相，可被外部 `RE` 覆盖）→ 文档“MAX13487/88 无 DE 脚”**正确** |
| 9.2 | `RE` 该接什么 | “Drive RE low to enable the RO. **Drive RE high to let the AutoDirection circuit control the receiver.**” | **RE 高 = 交给 AutoDirection（正常收发，且是热插拔后的默认态）**；RE 低 = 强制 RO 常开 |
| 9.3 | `SHDN` 该接什么 | “Drive SHDN high to let the device operate in normal operation. Drive SHDN low to put the part in shutdown.” | **SHDN 高 = 正常**，低 = 关断 → “接固定高电平”正确 |
| 9.4 | **EN 接法裁定** | 9.2 + 9.3 | **① MAX13487/88 → EN 接固定高电平**：在手册 `RE` / `SHDN` 两种诠释下**均成立**，文档口径获手册背书 ✅；② MAX485/3485 → EN 即 `DE`（高 = 发送），固定接高会占死总线，文档口径**正确** ✅ |
| 9.5 | **偏置电阻是必需项（本轮新发现）** | “Pullup and Pulldown Resistors” 一节：**“are required for proper operation of the device”**；无偏置时 AutoDirection 状态机会**保持驱动器使能** | 文档原把“4.7kΩ 偏置实测”列为**备注**，应升级为 **M3 功能验收项** —— 模块若无偏置，**从站永远收不到应答**（症状与“模块坏了”极像，会导致误判）→ 已回写 CTX 三.4 |
| 9.6 | `DI` 空闲态要求 | “require the DI input be driven high to remain in the idle state” | ESP32 UART TX 空闲即高（mark），**天然满足**，无需改代码 ✅ |
| 9.7 | 供电 | “VCC = +5V ±5%” | 与文档一致（MAX3485 变体才是 3.3V）✅ |

- **仍未闭环（本核实不能解决的）**：手册只证明**芯片侧**该怎么做，**不能证明模块侧**把那颗 `EN` 丝印引到了芯片的哪一脚（`RE`？`SHDN`？还是三合一款里 MAX485 变体的 `DE`）。**仍须实物丝印 + 模块走线（或产品资料）确认** —— H-1 降级但不消失。
