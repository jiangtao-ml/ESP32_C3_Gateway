## 0b. 线 A · 台面预演（**接真机之前必须先走完**）

> **为什么要多做这一步**：M5 的第一次烧录要一次改三处（功能码 `0x03`→`0x04`、默认 3 段读取、
> `RS485_CHAR_TIMEOUT_MS` 25→4~8）。如果直接接真机首跑，一旦不通，**无法判断是代码错、还是
> 真机 / 接线错** —— 那等于把 M4 踩过的坑（在错误假设上连续排查）再踩一遍。
>
> **做法**：485 总线另一头**先保持电脑（USB 转 485）**，用 `06_tests/m5_slave_04.py` 把
> 「`0x04` + 3 段 + 新超时」整条链路跑通，**再去碰真机**。
> 台面这一侧与 M4 完全同构 ⇒ **USB 供电即可，不需要充电宝**（判据见 §1 第 2 步）。

### A1 · 固件改动

内容见 §6（功能码 / 3 段宏 / `RS485_CHAR_TIMEOUT_MS` / 期望帧长 / 日志），交总控 / Codex。

### A2 · 起 `0x04` 从站模拟器（电脑侧，USB 转 485 接面包板总线）

| 要验的分支 | 命令 | 从站行为 |
| --- | --- | --- |
| 「一帧读全」成立（`QI_READ_SPLIT_3SEG = 0`） | `python 06_tests/m5_slave_04.py COM7` | 接受 `00 27`，回 **83 字节** |

## 0c. 现场单 · 无 USB 转 485 / 无串口时的首跑顺序（**2026-10-05 现场实际**）

> **适用**：真机 A/B **已接在 MAX13487 上**、配电箱**带电运行**、手边**没有 USB 转 485**。
> ⇒ ① **§0b 的台面预演跳过**（它需要把 485 另一头换成 USB 转 485）；
> ② 真机带电期间 USB 必须拔掉 ⇒ **运行期拿不到串口日志**，只能靠 UDP 判读。
> 对应施工指令：`04_ai_prompts/03_Codex提示词_M5功能码与3段读取.md`（P13 即为此刻准备的通道）。

### 开跑前（不需要别人帮忙）

| # | 动作 | 说明 |

| 0a | `ipconfig /all` 确认电脑 WLAN IP == `config.h` 的 `UDP_TARGET_IP` | **不一致就必须并入同一次烧录** —— 断电窗口只有一次，不能烧两遍 |

### 执行顺序（插 USB 的时刻**必须**落在「真机断电」窗口内）

| 步 | 动作 | 真机侧 | 谁做 |
| --- | --- | --- | --- |
| 1 | **给配电箱断电**（三相则断全三相；有条件就验电） | **断电** | 老师 / 电工 |

| 7 | 要看串口日志（`解析 OK` / `CRC 失败` / `帧长异常` 统计项）→ **回第 1 步** | 断电 | 老师 + 你 |

### 判据（此时只有 UDP 可用）

| UDP 看到 | 含义 | 下一步 |
| --- | --- | --- |
| `时间戳 \| <78 字节 HEX>` | 三段全通，物理链路成立 | 按 §4 核对 Q-08 主判据（原始寄存器值逐项相等） |
| `时间戳 \| FAIL:Sx:<原因>` | 该段失败，原因已标注 | 按 §8 速查定位 |
| 一直没有任何 UDP 行 | 与 485 无关：WiFi / 充电宝供电 / 目标 IP | 查 WiFi、供电、`UDP_TARGET_IP` |
| 有 `UNSYNCED` 行 | NTP 未对时（**不影响 485 判据**） | 记录即可，别当成 485 问题 |

> 🚨 每次插 USB 前**重新确认**配电箱处于断电状态 —— 不要凭"刚才断过"就认为现在没电。
> 💡 想省掉"每次看日志都要断一次电"的代价 ⇒ 买 **RS485 隔离模块**或 **USB 隔离器**（几十元）。

## 1. 🚨 安全协议（上电前必须逐条闭环，缺一不可）

### 第 0 步：断电 + 验电（**不做到这一步，不许打开箱盖、不许碰任何线**）

| # | 动作 | 判据 |
| --- | --- | --- |
| 0.1 | **确认有几路进线、以及是否三相**。配电箱可能不止一路（双电源 / 联络开关）；若为三相 380V，**必须断全三相**，只断一相仍然致命。**不确定就请电工。** | 进线路数与相数已数清（**断电后**看进线端子，或问电工） |
| 0.2 | 断开该箱总进线开关，**并挂"禁止合闸"标识**或让人看守 | 开关已在断开位 |
| 0.3 | **验电**：用**验电笔 / 万用表**逐个确认 —— ① 进线端子对 PE；② 进线端子对 N；③ 出线端子；④ **STB3-125 的 RS485 端子**。**每一处都必须无电。** | 全部测点均无电压指示 |
| 0.4 | 操作时**只用带绝缘手柄的工具**，**不徒手**碰端子，**不戴金属饰物**（手表、戒指、项链） | — |
| 0.5 | 脚下保持干燥、绝缘（穿绝缘鞋或站在干燥木/胶垫上），**一只手操作**（另一只手不扶箱体） | — |

> **为什么验电不能省**：可能出现"断错开关""双路供电""标识与实际不符"。**断电 ≠ 无电，必须验。**
> **如果你没有验电笔/万用表，或者不确定怎么验 —— 停手，找电工。** 这不是可以"先试试"的事。

### 第 1 步：接线（在已断电、已验电的前提下）

- 接线内容见 §2。接好后**先自查三遍**（A/B 有没有接反、有没有铜丝外露搭到相邻端子、GND 有没有接错），**再**合闸。
- 若是**第一次**接真机：**合闸前先不要接 ESP32 那一侧**。可以只把线引到箱外，用端子台做好绝缘，缩到箱外的动作在断电时完成。

### 第 2 步：供电隔离（运行时必须）

- **ESP32 由充电宝 / 手机充电器供电，USB 数据线拔掉**，电脑只通过 WiFi 收 UDP。
- **绝不允许「电脑 USB 供电 + 真机带电」同时存在** —— 这是"烧电脑主板"的唯一通路，也是导师明确警告的场景。
- ⚠️ **本项目现场照片显示：配电箱正下方就摆着一台带 USB/HDMI 接口的电脑底座。**
  "顺手插上 USB 看串口"是最方便的动作，也因此是最危险的动作。**烧录/看串口时，真机侧必须处于断电状态。**

### 第 3 步：强烈建议加 RS485 隔离模块（便宜的保险）

- 充电宝供电能保护"运行期间"的电脑，但**调试期间你必然要插 USB**（烧录 + 看串口），那正是风险最高的时刻。
- 加一个 **RS485 隔离模块**（ADM2483 / ADM2582 类芯片的成品模块，几十元），把 485 侧与 MCU 侧做**电气隔离**，
  这样**插着 USB 调试也安全**。
- 电力系统数据采集用隔离 485 是标准做法，不是过度设计。**建议在正式接真机前先买。**

### 第 4 步：其余电气检查

| # | 项 | 说明 |
| --- | --- | --- |
| 4.1 | **`RXO` 空闲电平实测** | 5V → 必须 1kΩ/2kΩ 分压后进 GPIO20；3.3V → 直连。目前为直连，电气合规性仍 `[待确认]` |
| 4.2 | **共地** | ESP32 GND / MAX13487 GND / 真机 485 口 GND 相连（**若已加隔离模块，则按隔离模块的接线要求处理两端地**） |
| 4.3 | **EN 固定高电平** | MAX13487，`RS485_DE_PIN = -1`；不得悬空 / 接 GND / 动态切换 |
| 4.4 | **只读不写** | 本阶段只允许 `0x04` 读输入寄存器。合闸/分闸/锁扣/解锁/复位/广播/写寄存器**一律禁止执行** |

### 第 5 步：真机侧信息确认（**断电状态下拍摄/核对，不要带电开箱拍照**）

**已确认（2026-10-04 用户实拍照片）：**

| 项 | 观察结果 |
| --- | --- |
| 配电箱 | **`GOOWANT PZ30`** 明装箱，透明（橙）防护盖 |
| 箱内器件 | `CHNT`（正泰）上级断路器 + **`STB3-125` 智能断路器（即 QI 采集设备）** + `国网电工` 面板 |
| 带电状态 | **面板红色指示灯点亮** ⇒ 该箱处于**带电运行**状态 |
| 标注 | `STB3-125` 上有 `400V~` 与 `RS485` 丝印；`国网电工` 面板有 `RS485` 丝印 |
| ⚠️ **疑似三相 380V，不是单相 220V** | 依据：① 铭牌 `400V~`（单相家电不会标 400V）；② `STB3-125` 协议里含 **A / B / C 三相**电压/电流/温度寄存器（见 `02_docs/06_QI协议说明.md` §5.3）。**若确为三相 ⇒ 任意两根相线之间都有 380V，断电必须断全三相，只断一相仍致命。** 真正确认需看配电箱进线（**断电后**）或问电工。 |

> ⚠️ **照片不能证明安全。** 电压等级、进线路数、端子定义、接地方式、是否有漏电保护 ——
> **一概不能从照片判断**，必须断电后用仪表实测。**任何"看着没问题"的推断都不成立。**

**待确认（必须断电后核对）：**

### 第 5b 步：取出的那对线 —— **信号线还是电源线？（必须两条独立证据认定）**

> 触发：用户已从箱内引出一对线（**白 + 橙**），并自行加了一个**绿色端子台**，准备接杜邦线。
> **⚠️ 在测出来之前，一律按"它带电"处理。不要接杜邦线，不要接到面包板。**

**证据 A：看箱内的接点丝印（断电后看）**

| 若这对线接在 | 则它是 | 危险等级 |
| --- | --- | --- |
| `STB3-125` 的 **`RS485` 端子**（丝印 `A` / `B`，可能还有 `GND`） | **信号线**（RS485 差分对） | 正常工作电压仅几伏，**但共模电位可能不为零**（见下） |
| `CHNT` 断路器 / `国网电工` 面板的 **`L` / `N` / `PE` 端子** | **电源线** | **220V / 380V，致命** |

**证据 B：仪表实测（这是唯一能定性的手段）**

用万用表 **AC 电压档**，逐个测：

| 测点 | 读数含义 |
| --- | --- |
| 白 ↔ 橙 | 有工频电压（数十~数百 V）⇒ **是电源线，停手** |
| 白 ↔ PE（接地） / 白 ↔ 箱体金属外壳 | **读数接近 0 且稳定** ⇒ 该线为低压参考（倾向信号线）；**出现 110/220/380V 量级 ⇒ 它带强电，停手** |
| 橙 ↔ PE / 橙 ↔ 箱体金属外壳 | 同上 |
| 白 ↔ N（若有中性线可测） | 同上 |

> ⚠️ **"颜色"不能作为判据。** 项目现场用的是**白护套多芯电缆**，白 / 橙都是**芯线颜色**，
> 不是国标相色（国标：黄/绿/红=三相、蓝=N、黄绿双色=PE）。**有人把两芯电源线挪用作信号线，也有人反过来**——
> 只看颜色必然出错。**必须"看箱内接点 + 实测"两条证据一致才能定性。**

> ⚠️ **即使是合法的 RS485 信号线，也不等于"可以随便接到电脑上"。**
> 这类设备的 485 侧常常**与强电部分非隔离**，A/B 相对大地的**共模电位可能不是 0**。
> 当你把一颗**接了 USB（因而接大地）的电脑**接进这条线时，就构成了**接地回路**——
> **这正是"烧电脑主板"的通路。** 这也是 §1 第 3 步强烈要求加 **RS485 隔离模块**的原因。

**在完成第 5b 步并有确定结论之前：**

1. **不要**把杜邦线接到这对线上。
2. **不要**让绿色端子台的**裸露螺丝**悬在外面无人看管 —— 若这对线带电，那些螺丝就是带电体。
3. 挂"禁止合闸"牌（若为了看箱内接点而断电，必须防止别人合闸）。
4. **若你不会用万用表测交流电压 —— 不要测，直接找老师/电工认线。**
   带电测量本身也有风险，这不该是"边学边试"的操作。

**用户已补充的现场事实（2026-10-04 23:02）—— 证据权重更新**

| 事实 | 对判定的影响 |
| --- | --- |
| 这对线**此前接的就是 USB 转 485 模块** | ⭐ **强证据**：USB 转 485 模块不可能接在强电上 ⇒ **几乎可确定为 RS485 信号线（A/B），不是 220V/380V 电源线。** 证据 B 过关。 |
| 装绿色端子台时**已拉闸断电** | ✅ 操作正确，安装态无触电风险。 |
| ⚠️ **但仍缺证据 A** | 需确认这对线在箱内接的就是 `STB3-125` 的 `RS485` 端子（丝印 `A`/`B`）。**两条证据一致才算闭环**；不过有了上一条强证据，此项已降为"确认性核对"而非"阻塞项"。 |
| ⚠️ 顺带值得问 | 之前那套「电脑 + USB 转 485 + 这对线」**通信成功过吗**？若成功过 ⇒ 该组合已被实证安全共存，风险进一步下降。 |

> 🚨 **必须纠正的一个口径（重要）："装的时候断电了、不带电" ≠ "此后一直安全"。**
>
> `不带电` 只对**安装那一刻**成立。**一旦合闸**，这对线就接到了 `STB3-125` 的 RS485 端子上，
> 它会带上 **RS485 的共模电位**——**相对大地可能不为零**（这类设备的 485 侧常与强电部分不隔离）。
>
> ⇒ **规矩是"每次改接线前都要再断一次电"，而不是"已经装好了就一直安全"。**
> ⇒ 这也是为什么 §1 第 3 步强烈建议加 **RS485 隔离模块**：它把这个问题从"每次都要断电"变成"插着 USB 也安全"。

### 第 6 步：**停手条件**（出现任一情况，立刻停，不要"再试一下"）

| 情况 | 处置 |
| --- | --- |
| **取出的一对线身份未定（不知是 RS485 还是电源线）** | **停手**。先做 §1 第 5b 步（看接点 + 实测），**不得靠颜色推断**。⚠️ 2026-10-04 已补充"此前接的就是 USB 转 485 模块"这一强证据 ⇒ 该项**已大幅降险**，仅剩箱内丝印的确认性核对 |
| 没有万用表 / 验电笔 | **停手**。先买，别开箱 |
| 不会用万用表测交流电压 | **停手**。**不要为了回答这个问题而"边学边测"** —— 带电测量的手法本身有风险，找电工 |
| 数不清箱内有几路进线，或不确定断的是哪一路 | **停手**，找电工 |
| 断电后验电，任一测点**仍有电压** | **停手**，说明没断对/有回电，找电工 |
| 接线时**手抖 / 看不清楚 / 光线不足 / 站姿不稳** | **停手**，宁可改天 |
| 有任何一秒觉得"这里可能带电" | **停手**，按"它带电"处理 |
| 有人可能误合闸（没有挂牌、没有看护） | **停手**，先把误合闸堵住 |
| 箱体有**烧灼痕迹 / 焦味 / 破损绝缘** | **停手**，找电工，不要自行处理 |

> **一条原则：这个阶段"多花一天"的成本 ≈ 0；一次触电或一块烧掉的主板，成本不可逆。**
> 分不清就停，问老师，问电工。**没有任何进度值得拿这个换。**

## 2. 硬件接线

> **接线动作全部在「已断电、已验电」状态下完成**（见 §1 第 0 步）。带电接线一律禁止。

### 2.1 M5 与 M4 的接线差异（只有一处）

| 环节 | M4（已通过） | M5 |
| --- | --- | --- |
| 485 总线另一侧 | 电脑 USB 转 485（Modbus 从站） | **QI 真机 STB3-125** |
| ESP32 逻辑侧 | `GPIO21`→模块 `RXD`、`GPIO20`←模块 `TXD`、`VCC`/`EN`→5V、共地 | **完全不变** |
| 供电 | 电脑 USB（烧录与运行同一根线） | **烧录时用电脑 USB；运行采样时改充电宝，拔掉 USB** |

### 2.2 总线侧接线

| MAX13487（蓝板 `RS485 V2.05`，丝印按**字母**接，不按位置） | → | QI 真机 485 端子 |
| --- | --- | --- |
| `A` | ↔ | `A`（如真机标注 A/B） |
| `B` | ↔ | `B` |
| `GND`（3 脚排最后一个） | ↔ | 真机 485 地（若有该端子） |

> ⚠️ 总线侧 3 脚丝印顺序是 **`B` / `A` / `GND`**（旧文档写 `GND/A/B` 是错的，见 `00_context.md` 红线 4b）。

### 2.3 箱外端子台 → 杜邦线（可靠性提示，非安全问题）

用户已在箱内引出的那对线上加了一个**绿色端子台**，准备用杜邦线接到面包板。功能上可行，但注意：

| 风险 | 说明 | 处置 |
| --- | --- | --- |
| **接触不良** | 多股杜邦线夹在螺钉端子下会**发丝散开**，拧紧后仍可能随时间松动、氧化 | **拧紧**；更稳的做法是杜邦线头**先上一点焊锡**再夹 |
| **随机丢帧 / 超时** | 上面这类接触问题在 485 上**不会表现为"不通"，而会表现为间歇性半帧 / CRC 失败 / 超时** —— 与 M4 踩过的坑同源，**极易误判成模块或固件问题** | 出现"偶发、随机"的失败时，**先怀疑接线接触**，不要先怀疑代码 |
| **走线长度** | A/B 走线越长、环路越大，抗干扰越差 | 尽量短；避开强电走线并行走 |
| **端子台裸露** | 端子台若悬在箱外，其螺丝在合闸后可能带共模电位 | 绝缘处理好；调试时**先断电再改线** |

## 5. E-02 决策树（M5 期间必须收敛）

```
第 2 步发 `00 27` 一帧读全
├─ 收到 83 字节合法响应 ──▶ 一帧读全成立
│                            ⇒ 删除分段路径；回写 06_QI §7 E-02 与 Errata
└─ 收到 `01 84 xx`（异常响应）或超时
     ⇒ 3 段成为正式方案 ⇒ E-02 结案（"原文上限 16 属实"）
```

**异常响应识别**：`01 84 xx yy zz` 中 `0x84 = 0x04 | 0x80`。固件已内建该分支
（`esp32c3_gateway.ino` 的 `parseResponse()` 第 (2) 段，会打印 `[M4]/[M5] 从站异常响应 FUNC=0x84 异常码=0x..`）。

## 7. 分步执行与判据

### 第 1 步：单帧探针（不循环，只发一次）

- **做法**：用 `06_tests/serial_capture.py` 抓 ESP32 串口；或将探针帧写进固件发一次。
  PC 侧也可直接注入（真机不接电脑，故**此步须由固件发**）。
- **判据**：串口出现 `解析 OK FUNC=0x04 DATA=` 且数据域为 2 字节（1 个寄存器）→ **物理链路 + 真机会应答**。
- **失败**：看 §8 速查。

### 第 2 步：一帧读全 vs 3 段（决定 E-02）

- 先试 `00 27`（仅一轮）；按 §5 决策树收敛。
- **判据**：得到 83 字节合法响应，或收到 `01 84 xx` 异常响应（两者都是"有结论"的结果，都算成功的一步）。

### 第 3 步：连续轮询 ≥60 s

- 判据：`解析 OK` 占比接近 100%；`CRC 失败` / `帧长异常` 为 0。
- 工具：`python 06_tests/serial_capture.py COM5 115200 60`（抓串口）或直接复用 `m4_verify.py` 的汇总逻辑。
- **观察项**：M4 出现过的**半帧**（`RX=n 期望 N`）是否再现 —— 真机是纯硬件 UART 无 USB 批量交付，
  **若仍出现半帧则说明问题不在 USB 侧**，需重估 `RS485_CHAR_TIMEOUT_MS`（见 `02_docs/15` §4.1）。

### 第 4 步：数据正确性核对（Q-08）

- **主判据**：**原始寄存器值完全相等** —— 把串口 `DATA=` 的 39 个寄存器与 `06_QI` §5.3 表逐项对照。
- **兜底**：工程量误差 ≤ **±0.5% 满量程**（各自量程）。
- **两条同时记录；兜底不改变主判据的判定。**

## 8. 失败判读速查

| 现象 | 含义 | 处置 |
| --- | --- | --- |
| `超时 … RX=0` 持续 | 去程断 / 真机未供电 / 真机地址不是 1 | 查接线；确认真机通信地址（默认 1）；确认真机 485 已启用 |
| `超时 … RX=0` 但**带外监测到总线有帧** | 发送正常、回程断 | 查 `RXO` → GPIO20 通路与分压 |
| `超时 … RX=1~n`（半帧） | 字节间隙过大 / 波特率不符 | 核对真机波特率是否 9600（出厂值）；阈值暂放 8ms 复测 |
| `从站异常响应 FUNC=0x84 异常码=0x02` | **E-02 命中**：寄存器地址/数量越界 | 切 3 段读取（§5） |
| `从站异常响应 FUNC=0x84 异常码=0x01/0x03` | 功能码不支持 / 数据值非法 | 核对功能码是否 0x04；核对寄存器数 |
| `CRC 失败` | 干扰 / 偏置不足 / 共地不良 | 查共地（最重要）、A/B 走线尽量短、偏置电阻是否板载 |
| 收到**乱码字节而非零字节** | **A/B 极性反** 或波特率不符 | 断电对调 A/B 两根线 |
| `解析 OK` 但数值荒谬 | 换算公式 / 寄存器偏移错 | 对照 §9 换算表与 `06_QI` §5.3 |
| 帧长 83 但 CRC 对、值全 0/全 F | 真机未接负载或该相无数据 | 正常现象，记录即可 |
