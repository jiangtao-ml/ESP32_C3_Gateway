## 0. 为什么必须分层搭

今晚一轮的核心教训：**一次接完就测 = 十个变量同时上场，任何一个错都表现为同一个现象（`RX=0`）**，无法定位。

本指南的原则：**每接一层，先验一层；上一层没验过，不接下一层。**

## 0.1 本轮已确立的事实（作为基线，不必重查）

| 项 | 结论 |
| --- | --- |
| **两个 USB 转 485 模块** | ✅ **收发都正常**（双端口互测双向 5/5）→ 均可继续使用 |
| 旧黑色模块（FTDI） | ✅ 同样是好的；其**真实缺陷只有"缺 GND 端子"**（真机上仍须换） |
| A↔A / B↔B 接法 | ✅ 验证有效 |
| ESP32 固件与烧录 | ✅ 无误（判据：IDE 输出须有 `Writing at 0x...` / `Hash of data verified.`） |
| **MAX13487 侧** | ❌ **故障在这里**（上一轮已收窄） |

## 0.2 材料清单

- ESP32-C3 SuperMini（HW-466AB）×1
- MAX13487 模块（蓝板，逻辑侧 5 脚 + 总线侧 3 脚）×1
- USB 转 485 模块 ×1（两个都可用，推荐**带 GND 端子的蓝色 CH340 那只**）
- 1kΩ 电阻 ×3（串成 1k + 2k 做分压）
- 杜邦线若干（**建议全部换新线**，旧线在今晚反复插拔过）

## 1. 第 1 步：清空 + 只插 ESP32

1. [ ] **拔掉所有杜邦线**；MAX13487 从面包板上取下。
2. [ ] USB 转 485 可以插在电脑上，但其 **A/B 保持悬空**（不接任何东西）。
3. [ ] **只插 ESP32 的 USB**。

**判据**（由 WorkBuddy 抓 COM5 判定）：串口每秒出现一行

```
[UDP -> 192.168.1.118:8888] 2026-10-04 HH:MM:SS | HEARTBEAT
```

- ✅ 有输出且时间是**正确的墙钟时间**（不是 `BOOT+xx`）→ 进第 2 步
- ❌ 无输出 → 先查 `USB CDC On Boot = Enabled` 与端口号（应为 COM5，`VID:PID 303A:1001`）

---

## 2. 第 2 步：验 GPIO20（**本轮最关键的一步**）

目的：一次性验掉 **GPIO21 输出 + GPIO20 输入 + UART1 + 烧录链路**，并彻底了结 **R-13「GPIO20 可能已被 5V 打坏」**。这一步**零外部依赖**，不涉及 MAX13487 与总线。

> ✅ **`config.h` 已由 WorkBuddy 预置**：`RS485_MODE_LOOPBACK_SELFTEST = 1`

1. [ ] **断电**，用一根杜邦线短接 **GPIO21 ↔ GPIO20**（SuperMini 上 USB-C **对侧那一排的末端两个脚**，先认板面丝印）。
2. [ ] 确认 **MAX13487 完全没有接**（避免 5V 灌进 GPIO20）。
3. [ ] 烧录并打开串口监视器（115200），**跑满 1 分钟**。

**判据**：每秒一行

```
[485] 回环 OK TX=8 RX=8 | 01 03 00 00 00 02 C4 0B
```

1 分钟后应出现 `[485] 统计：成功 60+ / 失败 0 / 超时 0`。

| 现象 | 结论 | 动作 |
| --- | --- | --- |
| 每秒 `回环 OK`，1 分钟 `成功 60+ / 失败 0 / 超时 0` | ✅ **GPIO20 完好，R-13 解除** | 进第 3 步 |
| `TIMEOUT ... RX=0`（短接线已确认插好、CDC 已 Enabled） | ❌ **GPIO20 输入通路已损坏** | **停下来报 WorkBuddy / 总控**：需改用 GPIO4 / 5 / 10 作 UART1 RX，并同步改 `config.h` 与文档 |
| `TIMEOUT ... RX=N`（0<N<8） | 半帧 | 换一根杜邦线重试；确认 MAX13487 确实没挂上 |

4. [ ] 测完：**拔掉那根短接线**，并把 `RS485_MODE_LOOPBACK_SELFTEST` **改回 `0`**（WorkBuddy 会处理，或由用户在 IDE 里改）。

## 3. 第 3 步：接 MAX13487 的「逻辑侧」（**先不接总线**）

> ### ⚠️ 先数脚，认准两侧
> MAX13487 模块（蓝板）**两排脚**：
> - **5 个脚的那一排 = 逻辑侧**（`GND / TXD / RXD / VCC / EN`）
> - **3 个脚的那一排 = 总线侧**（`B` / `A` / `GND`，**`GND` 在最后**）
>
> **A/B 只能接在「3 个脚那排」。** 误接在逻辑侧 = 总线开路，外观上却"看着是接好的"。

### 3.1 逻辑侧接线表

> ### ⚠️⚠️【2026-10-04 M4 实测确认】模块 `TXD`/`RXD` 是**交叉**约定，不是同名对接
>
> 模块丝印写的是**模块自身的收发方向**：
> - 模块 **`TXD` = 芯片 `RO`（接收输出）** → 应接 ESP32 的 **RX**
> - 模块 **`RXD` = 芯片 `DI`（发送输入）** → 应接 ESP32 的 **TX**
>
> **按"同名"接（`GPIO21`→`TXD`）会双向全断**：`GPIO21` 顶在芯片输出脚上对撞、芯片 `DI` 从未被驱动 → 驱动器一点差分都不输出；
> 同时 `GPIO20` 挂在 `DI`（高阻输入）→ 收不到任何东西。**此时模块电源灯仍会亮，极易误判成"模块坏/没供电"。**

| MAX13487（5 脚排，**按丝印认字母**） | 接到 | 说明 |
| --- | --- | --- |
| `GND` | ESP32 `G` | **必须共地** |
| **`RXD`** | ESP32 **`GPIO21`** | 芯片 `DI`（发送输入），3.3V 直驱 |
| **`TXD`** | ESP32 **`GPIO20`** | 芯片 `RO`（接收输出），见 3.2 |
| `VCC` | ESP32 `5V` | ⚠️ **必须 5V** |
| `EN` | ESP32 `5V` | **接固定高电平**；不得悬空 / 接地 / 动态切换 |

### 3.2 分压（3 个 1kΩ 电阻 → 1k + 2k）

```
MAX13487 RXO ──[1kΩ]──● 分压节点 ──[1kΩ]──[1kΩ]串起来── GND
                      │
                      └────── ESP32 GPIO20
```

- 上臂 **1kΩ ×1**；下臂 **2kΩ = 两个 1kΩ 串联**。
- 分压节点电压 ≈ `5V × 2/(1+2)` = **3.33V**。
- ⚠️ **严禁**只串一个 1kΩ 直连 GPIO20（不构成分压，5V 直灌 3.3V 引脚）。
- ⚠️ 下臂若只放一个 1kΩ → 分压点仅 2.5V，卡在 ESP32-C3 门限 2.475V 上，无余量。

### 3.3 本步判据

1. [ ] **断电**接线，接完复查一遍。
2. [ ] 上电，由 WorkBuddy 抓 COM5。

**预期**：ESP32 仍每秒 `HEARTBEAT`（不受影响），且 `[M4] 超时 ... RX=0`（**正常** —— 总线还没接，没人在应答）。

- ✅ 与预期一致 → 进第 4 步
- ❌ ESP32 掉线 / 重启循环 → 立刻断电，报 WorkBuddy（疑供电被拉垮）

## 4. 第 4 步：接「总线侧」，并对接 USB 转 485

> ### ⚠️⚠️ 先读丝印：3 脚排的顺序**不是** `GND/A/B`
>
> **2026-10-04 照片核实**：本模块（蓝板 `RS485 V2.05`）**3 脚排丝印从左到右是 `B`、`A`、`GND`** ——
> **`GND` 在最后，`B` 在最前**。项目旧文档写作 `GND / A / B`，**是错的**，据此接线会把 `B` 接到 `GND` 上、使总线差分永远出不去（症状 = 双向全断）。
>
> **一律按字母接，不要按位置接。**

| MAX13487（3 脚排，**按丝印认字母**） | 接到 |
| --- | --- |
| `A`（本模块在**中间**） | USB 转 485 的 `A` |
| `B`（本模块在**一端**） | USB 转 485 的 `B` |
| `GND`（本模块在**另一端**） | 面包板 `GND`（与 ESP32 同一点） |

- [ ] A 对 A、B 对 B，**不要交叉**。
- [ ] USB 转 485 的 **GND 端子也接到同一个 GND**（星形共地）。
- [ ] 走线**尽量短**，不要绕长线；插好后**逐根轻拉确认插到底**。

## 5. 第 5 步：双向联调（WorkBuddy 执行）

届时由 WorkBuddy 同时做两件事：

| 观察点 | 工具 | 看的现象 |
| --- | --- | --- |
| **回程**（电脑 → ESP32） | 从 COM7 注入字节 | ESP32 是否出现 `RX>0` |
| **去程**（ESP32 → 电脑） | COM7 起 Modbus 从站 | 从站日志是否收到合法请求帧 |
| 端到端 | COM5 串口 | 是否出现 `[M4] 解析 OK ADDR=1 FUNC=0x03 DATA=00 0A 00 14` |

**M4 通过判据**：每秒一行 `[M4] 解析 OK`，`REG: [0]=10 [1]=20`，连续 ≥60s 无超时 / CRC 失败 / 帧长异常。

### 失败判读（按方向分离）

| 去程 | 回程 | 结论 |
| --- | --- | --- |
| ❌ | ❌ | 总线仍不通 → 查 A/B 是否真接到「3 脚排」、VCC 是否 5V、共地 |
| ✅ | ❌ | **接收通路断** → 查分压（3.2）、`RXO`→`GPIO20` 那根线、GPIO20（回第 2 步） |
| ❌ | ✅ | **发送通路断** → 查 `GPIO21`→`TXD` 那根线、EN 是否接高 |
| ✅ | ✅ | 但无 `解析 OK` → 查从站参数（地址 1 / 9600 8N1 / 功能码 03 / 寄存器 0、1） |
