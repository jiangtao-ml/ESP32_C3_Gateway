# 01_firmware/esp32c3_gateway —— ESP32-C3 RS-485 采集网关固件主工程

本目录是「ESP32-C3 替换树莓派网关项目」的固件主工程（Arduino IDE sketch）。
当前处于 **阶段二 · M4（真实 485 总线收发 + Modbus RTU 解析）**：已实现联网、SNTP 对时、每秒 1 包 UDP 心跳、最小非阻塞状态机，以及 UART1 9600 8N1 每秒一轮 Modbus RTU 请求/响应（帧长驱动接收 + 三级超时 + 地址/功能码匹配 + CRC16/Modbus 校验 + 数据域提取）。
**尚未写 QI 真机协议**（M5 起用功能码 `0x04` 读输入寄存器）；M4 只用功能码 `0x03` 在电脑端 Modbus 从站上验证真实总线链路。

## 目录结构

```
01_firmware/esp32c3_gateway/
├── esp32c3_gateway.ino     # sketch 主文件（M4：WiFi + NTP + UDP 心跳 + 485 总线 Modbus RTU 收发/解析）
├── config.h               # 非敏感常量（电脑/自身 IP、端口、NTP、周期；485 超时与 Modbus 常量；已落实为实值）
├── secrets.h.example      # 凭据模板（占位符，不含真实值）
├── secrets.h              # ← 本地自建，不入库（.gitignore 已忽略）
└── README.md              # 本文件
```

sketch 目录名必须与 .ino 文件名一致（`esp32c3_gateway`），否则 Arduino IDE 无法识别。

## 首次搭建

1. 复制凭据模板并填写真实值（本文件不入库）：

   ```powershell
   Copy-Item .\secrets.h.example .\secrets.h
   ```

   然后编辑 `secrets.h`，把 `<占位符>` 换成实际 SSID / 密码。

2. 用 Arduino IDE 打开 `esp32c3_gateway.ino`。

## 构建方式（Arduino IDE）

| 项 | 设置 |
| --- | --- |
| 开发板 | ESP32C3 Dev Module（ESP32-C3 SuperMini） |
| **USB CDC On Boot** | **Enabled** ← 必需，否则 `Serial` 无输出 |
| Flash Size | 4MB (32Mb) |
| Upload Speed | 921600（不稳定时降到 115200） |
| Port | COM 号待 M1 查询（见根目录 README 第 8 节） |
| CPU Frequency | 160MHz |

关键设置：**USB CDC On Boot = Enabled**（此项是 `Serial` 有输出的前提）。

> ⚠️ **M3 起（含 M4）这是硬性要求**：若设为 Disabled，`Serial` 会落到 UART0，而 ESP32-C3 的 UART0 默认引脚正是 GPIO20/21 —— 会与 `Serial1` 争用同一对引脚，回环/总线收发必然异常。

UART1 参数（**M3 起已接入**，由 `setup()` 调用，形参顺序为 `(baud, config, RX, TX)`）：

```cpp
Serial1.begin(9600, SERIAL_8N1, 20, 21);   // RX=GPIO20, TX=GPIO21，9600 8N1
```

- 引脚：ESP32-C3 的 `HardwareSerial(1)` 可映射到 GPIO20/21（SuperMini 上无 USB/Flash 冲突）。
- `HardwareSerial(1)` 与 USB CDC（`Serial`）相互独立，可同时使用。
- RX 侧电平：MAX13487 的 RXO 若为空闲 5V，必须先 1kΩ/2kΩ 分压到约 3.33V 再接 GPIO20（M1 实测后再接线，见根目录 README 第 6 节）。

## M2：WiFi + NTP + UDP 联通验证

前提：本目录已有 `secrets.h`（含真实 SSID / 密码）；`config.h` 的 `UDP_TARGET_IP` / `LOCAL_IP` 与实测一致。

1. **电脑侧**：打开 **NetAssist（网络调试助手）**，协议选 **UDP**，本地端口填 **8888**（= `UDP_TARGET_PORT`），点「打开」。
2. 确认电脑无线网卡 IPv4 仍为 `192.168.1.117`（`ipconfig /all`）；若已变化，先改 `config.h` 再烧录。
3. 烧录固件并打开串口监视器（115200）。预期串口输出：

```text
[WIFI] 静态配置 IP=192.168.1.200 GW=192.168.1.1 MASK=255.255.255.0 DNS=192.168.1.1
[WIFI] 已发起连接（非阻塞），等待 wifiTick() 报告结果
[UDP] 本地端口 12345，目标 192.168.1.117:8888
[485] UART1 就绪 baud=9600 8N1 RX=GPIO20 TX=GPIO21
[485] 模式=真实 485 总线：ESP32(TX) -> MAX13487 -> 电脑 USB 转 485（Modbus 从站）
[485] ⚠️ RXO 必须 1k/2k 分压后接 GPIO20；EN 保持断开；三方必须共地
[485] 请求 8 字节 | 01 03 00 00 00 02 C4 0B  ->  期望响应 9 字节（从站地址 1，功能码 0x03 读 2 个保持寄存器）
[BOOT] M4 就绪：WiFi + NTP + UDP 心跳 + 485 总线收发 + Modbus RTU 解析
[WIFI] 已连接 SSID=xxx RSSI=-55 dBm IP=192.168.1.200 GW=192.168.1.1
[NTP] WiFi 已连上 -> 触发 SNTP 对时 TZ=CST-8 主=ntp.aliyun.com 备=203.107.6.88
[NTP] 时间已同步：本地 2026-09-27 20:15:03 +0800（TZ=CST-8，源 ntp.aliyun.com / 备选 203.107.6.88）
[UDP -> 192.168.1.117:8888] BOOT+5.012 | UNSYNCED
[UDP -> 192.168.1.117:8888] 2026-09-27 20:15:01 | M2_HEARTBEAT
```

4. **判定标准**（对应任务书 §9.1 M2）：
   - NetAssist 接收区**每秒出现 1 行**，格式 `YYYY-MM-DD HH:MM:SS | M2_HEARTBEAT`；
   - 对时完成前为 `BOOT+<秒>.<毫秒> | UNSYNCED`，对时完成后自动切换为墙钟时间；
   - **时区自检**：串口 `[NTP] 时间已同步` 行末尾应为 `+0800`（东八区）。若显示 `+0000`，说明 `NTP_TZ_INFO` 未生效（见 config.h 中关于不可写 `"<CST-8>"` 的注释）；
   - 连续 ≥60s 不断包（**从第 2 个包开始计时**，规避 ARP 首包丢失）。
5. **断网自恢复验证**：断开路由器 2.4GHz 约 30s 再恢复 → 串口应出现 `[WIFI] 连接断开` → `[WIFI] 第 N 次重连` → `[WIFI] 已连接` → `[NTP] WiFi 已连上 -> 触发 SNTP 对时`，且 **≤60s 内恢复发包**。

> 排查提示：NetAssist 收不到包 → 先看串口有无 `[WIFI] 已连接`（未连上则看 SSID 是否 2.4GHz）；再看 NetAssist 端口是否 8888 且已「打开」；最后确认电脑 IPv4 未变。

## M3：UART1 物理回环自测（内建，每秒自动一次）

目的：**先不接 MAX13487**，证明「串口能自发自收」，为 M4 的 Modbus 收发打底。
自测逻辑已内建在 `esp32c3_gateway.ino` 的 ST_TX / ST_WAIT_RX / ST_PARSE 中，**无需再手改代码**。

> ⚠️ **M4 起默认走真实总线模式**（`config.h` 里 `RS485_MODE_LOOPBACK_SELFTEST = 0`）。
> 要做本节回环自测，先把该宏改成 **`1`** 再烧录，测完**务必改回 `0`**。
> 若保持 `0` 直接短接 GPIO20/21，固件会按 9 字节响应帧等待，8 字节回环帧将被判为 `[M4] 帧长异常 期望 9 收到 8`（这不是故障，是模式不匹配）。

1. **断电**，用一根母-母杜邦线把 **GPIO21（TX1）与 GPIO20（RX1）短接**。
2. **不接 MAX13487**（避免总线偏置 / 终端电阻干扰判断，也避免 5V 电平灌进 GPIO20）。
3. 烧录并打开串口监视器（115200）。预期每秒一行：

```text
[485] UART1 就绪 baud=9600 8N1 RX=GPIO20 TX=GPIO21
[485] 模式=M3 物理回环自测：请短接 GPIO21 <-> GPIO20，且不接 MAX13487
[485] 回环 OK TX=8 RX=8 | 01 03 00 00 00 02 C4 0B
[485] 回环 OK TX=8 RX=8 | 01 03 00 00 00 02 C4 0B
...
[485] 统计：成功 100 / 失败 0 / 超时 0
```

4. **判定标准**（对应任务书 §9.1 M3）：
   - 每秒一行 `[485] 回环 OK TX=8 RX=8`，帧内容与 `01 03 00 00 00 02 C4 0B` **完全一致**；
   - **连续 1 分钟无 FAIL / TIMEOUT**（≥60 次全 OK）；跑到 1000 次时误帧 0、丢帧 0；
   - 每 100 次打印一次 `[485] 统计：成功 X / 失败 Y / 超时 Z`，其中 **Y 与 Z 应恒为 0**。
5. **失败判读**：
   - `TIMEOUT ... RX=0` → 短接线未插好 / 插错引脚，或 `USB CDC On Boot` 不是 Enabled（见上）；
   - `TIMEOUT ... RX=N`（0<N<8）→ 半帧，查杜邦线接触，或确认 MAX13487 是否仍挂在总线上；
   - `FAIL ... 期望 ... 收到 ...` → 后面紧跟的 `[差异] byte[i]` 会指出具体错位字节。

> ⚠️ 回环自测必须**先断开 MAX13487**，避免总线偏置 / 终端电阻干扰判断。

> 三级超时（均可调，见 `config.h`）：首字节 **80ms** → 字节间静默 **4ms** 判定本帧结束 → 整帧兜底 **300ms**。
> 发送后另有 **2ms** 保护间隔（`RS485_TX_GUARD_MS`）。9600 8N1 下 8 字节仅约 8.3ms，余量充足。

## M4：真实 485 总线收发 + Modbus RTU 解析（当前里程碑）

目的：把 ESP32 从「自己发自己收」接到**真实 485 总线**上。ESP32 每秒发一帧 Modbus RTU 请求，
电脑端用 **USB 转 485 模块 + Modbus 从站模拟器**应答，ESP32 校验响应帧并打印解析结果。
M4 只用功能码 `0x03`（读 2 个保持寄存器）验证**物理链路与解析**，**QI 真机协议留待 M5**。

请求帧（`config.h` 的 `MODBUS_TEST_FRAME`，已含独立复算的 CRC）：

```text
01 03 00 00 00 02 C4 0B
│  │  └──┬──┘ └──┬──┘ └──┬──┘
│  │     │       │       └── CRC16/Modbus = 0x0BC4，低字节在前（C4 0B）
│  │     │       └────────── 读 2 个寄存器
│  │     └────────────────── 起始地址 0x0000
│  └──────────────────────── 功能码 0x03（读保持寄存器）
└─────────────────────────── 从站地址 1
```

期望响应帧长 = **9 字节**：地址 1 + 功能 1 + 字节数 1 + 数据 4 + CRC 2。

### 接线（三方必须共地）

| 连接 | ESP32-C3 SuperMini | MAX13487 模块 | 说明 |
| --- | --- | --- | --- |
| 供电 | `5V` | `VCC` | ⚠️ MAX13487 **必须 5V**，不要接 3.3V |
| 发送 | `GPIO21`（TX1） | `DI` | 3.3V 逻辑可直驱 DI，无需电平转换 |
| 接收 | `GPIO20`（RX1） | `RXO`（= RO / RXD）**经 1kΩ/2kΩ 分压后** | ⚠️ 见下方醒目框；先实测 RXO 空闲电平 |
| 地 | `GND` | `GND` | ⚠️ **必须共地** |
| 总线 | — | `A(+)` / `B(-)` | 与 USB 转 485 模块的 `A(+)` / `B(-)` 一一对应接好 |
| 电脑侧 | — | — | USB 转 485 模块的 A/B 并在同一条总线上，其 `GND` 也必须并入上述共地点 |
| 控制 | — | `EN` | ⚠️ **保持断开**（见下方醒目框） |

```text
共地拓扑（星形，务必连到同一点）：
  ESP32-C3 GND ──┬── MAX13487 GND
                 └── USB 转 485 模块 GND
```

> ### ⚠️⚠️ RXO 必须 1kΩ/2kΩ 分压后才能接 GPIO20
>
> ```text
> MAX13487 RXO ──[1kΩ]── ● 分压节点 ──[2kΩ]── GND
>                        └── ESP32 GPIO20（约 3.33V）
> ```
>
> - **严禁** `2kΩ 接 RXO、1kΩ 接 GND`：分压点仅约 1.67V，低于 ESP32-C3 的高电平门限，必然收不到高电平。
> - **严禁**只串一个 1kΩ 就直接进 GPIO20（不构成分压，5V 会灌进 3.3V 引脚）。
> - **上电前先用万用表实测 RXO 空闲电平**：若已是 3.3V → 直连 GPIO20，不再分压；若为 5V → 必须按上图分压。

> ### ⚠️⚠️ EN 保持断开
>
> MAX13487 模块丝印 `EN` 的**含义尚未确认**（可能对应 `RE#`，也可能对应 `DE`，两者接法完全不同）。
> 未完成实测确认前：**既不接 3.3V，也不接 GND，也不接线**。详见根目录 README 第 6.1 节。

> 本节为**占位**：待用户选定工具后回填具体操作步骤（串口、波特率、从站地址、寄存器初值）。

| 候选 | 形态 | 说明 | 状态 |
| --- | --- | --- | --- |
| Modbus Slave（Witte Software） | 图形界面 | 最主流：新建从站、设从站地址 1、给 0x03 寄存器填初值即可应答 | 待用户确认 |

选定后需在模拟器中设定：**从站地址 1**、**9600 / 8N1 / 无校验**、**保持寄存器 0x0000 起 2 个**（值任填，例如 10 / 20）。

### 用户操作步骤

1. **断电**接线：按上表接 ESP32 ↔ MAX13487 ↔ USB 转 485，**先完成三方共地**。
2. **上电前**用万用表测 MAX13487 的 RXO 空闲电平，据此决定直连还是分压（见醒目框）。`EN` 保持断开。
3. 电脑插上 USB 转 485，在设备管理器确认 COM 号，打开从站模拟器并按上节参数设好。
4. 烧录固件（`RS485_MODE_LOOPBACK_SELFTEST = 0`），打开串口监视器（115200）。

### 预期输出

```text
[485] 模式=真实 485 总线：ESP32(TX) -> MAX13487 -> 电脑 USB 转 485（Modbus 从站）
[485] ⚠️ RXO 必须 1k/2k 分压后接 GPIO20；EN 保持断开；三方必须共地
[485] 请求 8 字节 | 01 03 00 00 00 02 C4 0B  ->  期望响应 9 字节（从站地址 1，功能码 0x03 读 2 个保持寄存器）
[M4] 解析 OK ADDR=1 FUNC=0x03 DATA=00 0A 00 14
      REG: [0]=10 [1]=20  CRC=3EDA
[M4] 解析 OK ADDR=1 FUNC=0x03 DATA=00 0A 00 14
      REG: [0]=10 [1]=20  CRC=3EDA
...
[485] 统计：成功 100 / 失败 0 / 超时 0
```

### 判定标准（M4 通过条件）

- 每秒一行 `[M4] 解析 OK ADDR=1 FUNC=0x03 DATA=...`，且 `REG:` 值与电脑端从站设定**一致**；
- **连续 ≥60s 无** `[M4] 超时` / `[M4] CRC 失败` / `[M4] 帧长异常` / `[M4] 地址不匹配`；
- 每 100 次累计打印 `[485] 统计：成功 100 / 失败 0 / 超时 0`（1000 次时误帧 0、丢帧 0）。

### 失败判读

| 现象 | 可能原因 |
| --- | --- |
| `[M4] 超时 ... RX=0` | 未共地 / `A(+)`、`B(-)` 接反 / MAX13487 未接 5V / `EN` 误接 / RXO 未接入 GPIO20 或分压接错 |
| `[M4] 超时 ... RX=N`（0<N<9） | 波特率或帧格式不一致（须 9600 8N1 无校验）/ 半帧（线缆接触、总线反射） |
| `[M4] 帧长异常 期望 9 收到 8` 且紧跟 `[诊断] RX 帧 == TX 帧` | **自发自收回显**：MAX13487 的 `RE#`/`EN` 被常开使能，先查 `EN` 是否误接 |
| `[M4] 地址不匹配 期望 1 收到 N` | 从站模拟器地址不是 1，或帧错位 |
| `[M4] CRC 失败 期望 XXXX 计算 YYYY` | 从站 CRC 字节序不是「低字节在前」（应为 `低字节 高字节`）/ 线路噪声误码 |
| `[M4] 从站异常响应 FUNC=0x83 异常码=0x02` | 从站不存在该寄存器地址（`0x02` = 非法数据地址），改从站寄存器配置 |

> 三级超时 + 帧长驱动（均在 `config.h`）：首字节 **80ms** → 字节间静默 **4ms** → 收满 **9 字节**立即结束 → 整帧兜底 **300ms**。
> 发送后另有 **2ms** 保护间隔（`RS485_TX_GUARD_MS`）。真实总线上若**稳定丢首字节**，优先把该值调到 **3~5ms** 复测。

> 回归自测：改回 `RS485_MODE_LOOPBACK_SELFTEST = 1` + 短接 GPIO20/21，即可复跑 M3 的物理回环自测，
> 用于在怀疑「串口层」故障时快速区分是**串口问题**还是**485 收发器 / 总线问题**。
