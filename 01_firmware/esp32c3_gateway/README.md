## 首次搭建


   然后编辑 `secrets.h`，把 `<占位符>` 换成实际 SSID / 密码。

2. 用 Arduino IDE 打开 `esp32c3_gateway.ino`。

## 构建方式（Arduino IDE）

| 项 | 设置 |
| --- | --- |
| 开发板 | ESP32C3 Dev Module（ESP32-C3 SuperMini） |
| **USB CDC On Boot** | **Enabled** ← 必需，否则 `Serial` 无输出 |
| Flash Size | 4MB (32Mb) |
| Upload Speed | 921600（不稳定时降到 115200） |
| Port | **COM5**（`303A:1001`，原生 USB CDC；换 USB 口会变）。⚠️ 烧前关掉 Arduino IDE 串口监视器，否则报 `PermissionError(13)` |
| CPU Frequency | 160MHz |

关键设置：**USB CDC On Boot = Enabled**（此项是 `Serial` 有输出的前提）。

> ⚠️ **M3 起（含 M4）这是硬性要求**：若设为 Disabled，`Serial` 会落到 UART0，而 ESP32-C3 的 UART0 默认引脚正是 GPIO20/21 —— 会与 `Serial1` 争用同一对引脚，回环/总线收发必然异常。

> 命令行编译（可选，与上面的 IDE 设置等价；在仓库根目录执行）：

```powershell
arduino-cli compile --fqbn "esp32:esp32:esp32c3:CDCOnBoot=cdc" 01_firmware/esp32c3_gateway
```

> `CDCOnBoot=cdc` 不可省。烧录用同一条命令末尾加 `--upload -p COM5`。
>
> **编译基线（`--clean`，core `esp32:esp32 3.3.10-cn`）**：
> - M4 期（2026-10-03，Codex）：Flash **997299 B (76%)** / RAM **38244 B (11%)**
> - NTP 三源改造后（2026-10-05，Codex）：Flash **999293** / RAM **38308**
> - **M5 + 功能对齐批次 1 后（2026-10-06，WorkBuddy 独立复现）：Flash `1004579 B (76%)` / RAM `39108 B (11%)`，0 error / 0 warning** ← **当前基线**

UART1 参数（**M3 起已接入**，由 `setup()` 调用，形参顺序为 `(baud, config, RX, TX)`）：

```cpp
Serial1.begin(9600, SERIAL_8N1, 20, 21);   // RX=GPIO20, TX=GPIO21，9600 8N1
```

- 引脚：ESP32-C3 的 `HardwareSerial(1)` 可映射到 GPIO20/21（SuperMini 上无 USB/Flash 冲突）。
- `HardwareSerial(1)` 与 USB CDC（`Serial`）相互独立，可同时使用。
- RX 侧电平：MAX13487 的 RXO 若为空闲 5V，必须先 1kΩ/2kΩ 分压到约 3.33V 再接 GPIO20（M1 实测后再接线，见根目录 README 第 6 节）。

## M2：WiFi + NTP + UDP 联通验证（**历史记录** · 2026-09-27；示例中的 IP / NTP 源 / `HEARTBEAT` 载荷均为当时真值）

前提：本目录已有 `secrets.h`（含真实 SSID / 密码）；`config.h` 的 `UDP_TARGET_IP` / `LOCAL_IP` 与实测一致。

1. **电脑侧**：打开 **NetAssist（网络调试助手）**，协议选 **UDP**，本地端口填 **8888**（= `UDP_TARGET_PORT`），点「打开」。
2. 确认电脑无线网卡 IPv4 仍为 `192.168.1.118`（`ipconfig /all`；**会随网络漂移**，2026-10-04 实测值，原 `.117`）；若已变化，先改 `config.h` 再烧录。
3. 烧录固件并打开串口监视器（115200）。预期串口输出：

```text
[WIFI] 静态配置 IP=192.168.1.200 GW=192.168.1.1 MASK=255.255.255.0 DNS=192.168.1.1
[WIFI] 已发起连接（非阻塞），等待 wifiTick() 报告结果
[UDP] 本地端口 12345，目标 192.168.1.118:8888
[485] UART1 就绪 baud=9600 8N1 RX=GPIO20 TX=GPIO21
[485] 模式=真实 485 总线：ESP32(TX) -> MAX13487 -> 电脑 USB 转 485（Modbus 从站）
[485] ⚠️ RXO 先万用表实测空闲电平：5V 必须 1k/2k 分压后接 GPIO20，3.3V 则直连不分压（未实测前按 5V 处理）；EN 接法随实物芯片型号二选一（MAX13487/13488 → 固定高电平；MAX485/MAX3485 → 方向控制 GPIO），先读丝印；三方必须共地。方向控制宏：MAX485 / MAX3485 → 把 config.h 的 RS485_DE_PIN 改成 EN 所接的 GPIO 号（默认 -1 = 不启用）
[485] 请求 8 字节 | 01 03 00 00 00 02 C4 0B  ->  期望响应 9 字节（从站地址 1，功能码 0x03 读 2 个保持寄存器）
[BOOT] M4 就绪：WiFi + NTP + UDP 心跳 + 485 总线收发 + Modbus RTU 解析
[WIFI] 已连接 SSID=xxx RSSI=-55 dBm IP=192.168.1.200 GW=192.168.1.1
[NTP] WiFi 已连上 -> 触发 SNTP 对时 TZ=CST-8 主=ntp.aliyun.com 备=203.107.6.88
[NTP] 时间已同步：本地 2026-09-27 20:15:03 +0800（TZ=CST-8，源 ntp.aliyun.com / 备选 203.107.6.88）
[UDP -> 192.168.1.118:8888] BOOT+5.012 | UNSYNCED
[UDP -> 192.168.1.118:8888] 2026-09-27 20:15:01 | HEARTBEAT
```

> 说明：本样例中的 UDP 目标为 **`192.168.1.118`**（= 当前 `config.h` 的 `UDP_TARGET_IP`）。
> 2026-09-27 首测时电脑为 `192.168.1.117`，**2026-10-04 实测漂移到 `.118`**；该值会随网络变化，以 `ipconfig /all` 为准。

4. **判定标准**（对应任务书 §9.1 M2）：
   - NetAssist 接收区**每秒出现 1 行**，格式 `YYYY-MM-DD HH:MM:SS | HEARTBEAT`（M4 起心跳标签为 `HEARTBEAT`；M2 阶段当时为 `M2_HEARTBEAT`，属历史记录）；
   - 对时完成前为 `BOOT+<秒>.<毫秒> | UNSYNCED`，对时完成后自动切换为墙钟时间；
   - **时区自检**：串口 `[NTP] 时间已同步` 行末尾应为 `+0800`（东八区）。若显示 `+0000`，说明 `NTP_TZ_INFO` 未生效（见 config.h 中关于不可写 `"<CST-8>"` 的注释）；
   - 连续 ≥60s 不断包（**从第 2 个包开始计时**，规避 ARP 首包丢失）。
5. **断网自恢复验证**：断开路由器 2.4GHz 约 30s 再恢复 → 串口应出现 `[WIFI] 连接断开` → `[WIFI] 第 N 次重连` → `[WIFI] 已连接` → `[NTP] WiFi 已连上 -> 触发 SNTP 对时`，且 **≤60s 内恢复发包**。

> 排查提示：NetAssist 收不到包 → 先看串口有无 `[WIFI] 已连接`（未连上则看 SSID 是否 2.4GHz）；再看 NetAssist 端口是否 8888 且已「打开」；最后确认电脑 IPv4 未变。

## M3：UART1 物理回环自测（内建，每秒自动一次）

目的：**先不接 MAX13487**，证明「串口能自发自收」，为 M4 的 Modbus 收发打底。
自测逻辑已内建在 `esp32c3_gateway.ino` 的 ST_TX / ST_WAIT_RX / ST_PARSE 中，**无需再手改代码**。

> ⚠️ **M4 起默认走真实总线模式**（`config.h` 里 `RS485_MODE_LOOPBACK_SELFTEST = 0`）。
> 要做本节回环自测，先把该宏改成 **`1`** 再烧录，测完**务必改回 `0`**。
> 若保持 `0` 直接短接 GPIO20/21，固件会按 9 字节响应帧等待，8 字节回环帧将被判为 `[M4] 帧长异常 期望 9 收到 8`（这不是故障，是模式不匹配）。

1. **断电**，用一根母-母杜邦线把 **GPIO21（TX1）与 GPIO20（RX1）短接**。
2. **不接 MAX13487**（避免总线偏置 / 终端电阻干扰判断，也避免 5V 电平灌进 GPIO20）。
3. 烧录并打开串口监视器（115200）。预期每秒一行：

```text
[485] UART1 就绪 baud=9600 8N1 RX=GPIO20 TX=GPIO21
[485] 模式=M3 物理回环自测：请短接 GPIO21 <-> GPIO20，且不接 MAX13487
[485] 回环 OK TX=8 RX=8 | 01 03 00 00 00 02 C4 0B
[485] 回环 OK TX=8 RX=8 | 01 03 00 00 00 02 C4 0B
...
[485] 统计：成功 100 / 失败 0 / 超时 0
```

4. **判定标准**（对应任务书 §9.1 M3）：
   - 每秒一行 `[485] 回环 OK TX=8 RX=8`，帧内容与 `01 03 00 00 00 02 C4 0B` **完全一致**；
   - **连续 1 分钟无 FAIL / TIMEOUT**（≥60 次全 OK）；跑到 1000 次时误帧 0、丢帧 0；
   - 每 100 次打印一次 `[485] 统计：成功 X / 失败 Y / 超时 Z`，其中 **Y 与 Z 应恒为 0**。
5. **失败判读**：
   - `TIMEOUT ... RX=0` → 短接线未插好 / 插错引脚，或 `USB CDC On Boot` 不是 Enabled（见上）；
   - `TIMEOUT ... RX=N`（0<N<8）→ 半帧，查杜邦线接触，或确认 MAX13487 是否仍挂在总线上；
   - `FAIL ... 期望 ... 收到 ...` → 后面紧跟的 `[差异] byte[i]` 会指出具体错位字节。

> ⚠️ 回环自测必须**先断开 MAX13487**，避免总线偏置 / 终端电阻干扰判断。

> 三级超时（均可调，见 `config.h`）：首字节 **80ms** → 字节间静默 **4ms** 判定本帧结束 → 整帧兜底 **300ms**。
> 发送后另有 **2ms** 保护间隔（`RS485_TX_GUARD_MS`）。9600 8N1 下 8 字节仅约 8.3ms，余量充足。

## M4：真实 485 总线收发 + Modbus RTU 解析（✅ **已完成，留作回归参考** · 2026-10-04）

目的：把 ESP32 从「自己发自己收」接到**真实 485 总线**上。ESP32 每秒发一帧 Modbus RTU 请求，
电脑端用 **USB 转 485 模块 + Modbus 从站模拟器**应答，ESP32 校验响应帧并打印解析结果。
M4 只用功能码 `0x03`（读 2 个保持寄存器）验证**物理链路与解析**，**QI 真机协议留待 M5**。

请求帧（`config.h` 的 `MODBUS_TEST_FRAME`，已含独立复算的 CRC）：

```text
01 03 00 00 00 02 C4 0B
│  │  └──┬──┘ └──┬──┘ └──┬──┘
│  │     │       │       └── CRC16/Modbus = 0x0BC4，低字节在前（C4 0B）
│  │     │       └────────── 读 2 个寄存器
│  │     └────────────────── 起始地址 0x0000
│  └──────────────────────── 功能码 0x03（读保持寄存器）
└─────────────────────────── 从站地址 1
```

期望响应帧长 = **9 字节**：地址 1 + 功能 1 + 字节数 1 + 数据 4 + CRC 2。

### 接线（三方必须共地）

> ### ⚠️⚠️【2026-10-04 M4 实测确认】下表用的是**芯片引脚名**，与**模块丝印**的对应关系是「交叉」的
>
> 模块丝印写的是**模块自身的收发方向**，不是"你那边接什么"：
>
> | 芯片引脚（下表用名） | 模块丝印 | 应接到 ESP32 |
> | --- | --- | --- |
> | `DI`（驱动**输入**） | **`RXD`** | `GPIO21`（TX） |
> | `RO`（接收**输出**） | **`TXD`**（别名 `RXO`） | `GPIO20`（RX） |
> | `VCC` / `GND` / `EN` | 同名 | `5V` / `G` / `5V` |
>
> **即：`GPIO21` → 模块 `RXD`；`GPIO20` ← 模块 `TXD`。**
> 按"同名对接"（`GPIO21`→模块 `TXD`）会**双向全断**（`GPIO21` 顶在芯片输出脚上对撞、`DI` 从未被驱动），**而模块电源灯仍亮**，极易误判为硬件故障。
> 本项即 M4 卡 5 天的真凶，详见 `02_docs/14_M4排障全过程复盘_2026-10-04.md`。
>
> 另注：**总线侧 3 脚丝印顺序为 `B` / `A` / `GND`**（`GND` 在最后），旧材料记作 `GND / A / B` 是错的。

| 连接 | ESP32-C3 SuperMini | MAX13487 模块 | 说明 |
| --- | --- | --- | --- |
| 供电 | `5V` | `VCC` | ⚠️ MAX13487 **必须 5V**，不要接 3.3V |
| 发送 | `GPIO21`（TX1） | `DI` | 3.3V 逻辑可直驱 DI，无需电平转换 |
| 接收 | `GPIO20`（RX1） | `RXO`（= RO / RXD）**经 1kΩ/2kΩ 分压后** | ⚠️ 见下方醒目框；先实测 RXO 空闲电平 |
| 地 | `GND` | `GND` | ⚠️ **必须共地** |
| 总线 | — | `A(+)` / `B(-)` | 与 USB 转 485 模块的 `A(+)` / `B(-)` 一一对应接好 |
| 电脑侧 | — | — | USB 转 485 模块的 A/B 并在同一条总线上，其 `GND` 也必须并入上述共地点 |
| 控制 | — | `EN` | ⚠️ **接法随实物芯片型号二选一**（`MAX13487 / MAX13488` → 接固定高电平 VCC/5V；`MAX485 / MAX3485` → 接方向控制 GPIO，需改造固件）。**先读实物 8 脚芯片丝印，未读前不得接任何电平**（见下方醒目框） |

```text
共地拓扑（星形，务必连到同一点）：
  ESP32-C3 GND ──┬── MAX13487 GND
                 └── USB 转 485 模块 GND
```

> ### ⚠️⚠️ RXO 空闲电平必须先实测（Q-10），据此决定是否分压
>
> ```text
> MAX13487 RXO ──[1kΩ]── ● 分压节点 ──[2kΩ]── GND（**仅当实测 RXO 空闲为 5V 时**）
>                        └── ESP32 GPIO20（约 3.33V）
> ```
>
> - **严禁** `2kΩ 接 RXO、1kΩ 接 GND`：分压点仅约 1.67V，低于 ESP32-C3 的高电平门限，必然收不到高电平。
> - **严禁**只串一个 1kΩ 就直接进 GPIO20（不构成分压，5V 会灌进 3.3V 引脚）。
> - **上电前先用万用表实测 RXO 空闲电平**：若已是 3.3V → 直连 GPIO20，不再分压；若为 5V → 必须按上图分压。

> ### ⚠️⚠️ EN 接法：随实物芯片型号二选一，先读丝印
>
> 模块丝印 `EN` 的**含义随主芯片型号而变**：`MAX13487 / MAX13488` 上是 `RE#` 或 `SHDN#`（**接固定高电平即正确**）；`MAX485 / MAX3485` 上是方向控制脚（**必须由 GPIO 动态切换**，固定接高会占死总线）。
> **接线前必须先读实物 8 脚芯片丝印定型；丝印未读前不得给 EN 接任何电平。** 详见根目录 README 第 6.1 节与 `04_ai_prompts/00_context.md` 三.5。
>
> ### ⚠️⚠️（阻塞）先确认实物主芯片型号，再谈 EN
>
> 本模块所在商品页是**三合一款**：`MAX3485`（3.3V **单向**）/ `MAX485`（5V **单向**）/ `MAX13487`（5V **双向**）。
> 商品图上的芯片丝印是 `MAX485 ESA`。**三者的 EN 语义完全不同**：
>
> | 实物芯片 | 方向控制 | `EN` 该怎么接 |
> | --- | --- | --- |
> | MAX13487 / MAX13488（5V 双向） | 自动，无需控制脚（芯片**无 `DE` 脚**） | **接固定高电平**（模块 VCC/5V，3.3V 亦可）；**不得悬空 / 接 GND / 动态切换**。悬空若对应 `SHDN#` 会关断器件（症状 = `RX=0`） |
> | MAX485 / MAX3485（单向） | **必须**由 MCU 切 DE/RE | **必须接 GPIO 动态切换**；固定接高 = **占死总线**。本固件**已内建** `RS485_DE_PIN`：把 EN 所接 GPIO 号填入 `config.h` 即启用（默认 `-1` 不启用；实测方向相反时改 `RS485_DE_ACTIVE_HIGH`） |
>
> **接线前必须先读实物芯片丝印确认**。若为 MAX485 / MAX3485，把 `config.h` 的 `RS485_DE_PIN` 设为 EN 所接 GPIO 号后重新编译即可（无需改固件逻辑）。
>
> #### MAX13487E / 13488E 数据手册要点（**仅对 `MAX13487 / MAX13488` 成立**）
>
> 引脚（8 脚 SO）：`1 RO / 2 RE# / 3 SHDN# / 4 DI / 5 GND / 6 A / 7 B / 8 VCC` —— **无 `DE` 脚**。
> - `RE#`：拉低 → `RO` 常使能；拉高 → **交 AutoDirection 控制接收器**。
> - `SHDN#`：**拉高才正常工作**；拉低 → 关断器件。
> - **`DI` 空闲须为高电平**（数据手册 Idle State 要求），**不要在 `DI` 上加下拉**。

### 电脑端 Modbus 从站模拟器：**Modbus Slave**（用户已选定）

| 项 | 设定 |
| --- | --- |
| 工具 | **Modbus Slave**（Witte Software），官网 modbustools.com |
| 连接 | `Connection` -> `Connect` -> **Serial Port**，选中 USB 转 485 对应的 COM 口 |
| 模式 | **RTU**；波特率 **9600**、数据位 **8**、校验 **None**、停止位 **1**、无流控 |
| 从站 | `Setup` -> `Slave Definition`：**Slave ID = 1** |
| 功能 | 选 **03: Read Holding Registers**；`Address` = **0**、`Quantity`/**Length = 2**、`Mode` = `Dec` |
| 数据 | 双击 `0` / `1` 两行填任意值，例如 **10** 与 **20**（对应固件打印 `[0]=10 [1]=20`） |
| 应答 | 保持窗口打开并已 `Connect`；Modbus Slave 收到请求会自动回帧 |

> 备选：`pymodbus`（Python，`pip install pymodbus`）以脚本方式起 RTU 从站，便于复现与自动化；若 Modbus Slave 的显示不直观，可换用它。二者任选其一，**不要同时占用同一个 COM 口**。

> ⚠️ Modbus Slave 是**共享软件**：未注册时每次运行限时约 10 分钟且会弹窗。M4 验收需连续 ≥1 分钟，
> 时间够用；若超时弹窗导致断开，重新 `Connect` 即可。

### 用户操作步骤

1. **断电**接线：按上表接 ESP32 ↔ MAX13487 ↔ USB 转 485，**先完成三方共地**。
2. **上电前**用万用表测模块的 RXO 空闲电平，据此决定直连还是分压（见醒目框）。`EN` 按实物芯片丝印结论接入（`MAX13487 / MAX13488` → 固定高电平；`MAX485 / MAX3485` → 方向控制 GPIO）；**丝印未读前不得接任何电平**。
3. 电脑插上 USB 转 485，在设备管理器确认 COM 号，打开从站模拟器并按上节参数设好。
4. 烧录固件（`RS485_MODE_LOOPBACK_SELFTEST = 0`），打开串口监视器（115200）。

### 预期输出

```text
[485] 请求 8 字节 | 01 03 00 00 00 02 C4 0B  ->  期望响应 9 字节（从站地址 1，功能码 0x03 读 2 个保持寄存器）
[M4] 解析 OK ADDR=1 FUNC=0x03 DATA=00 0A 00 14
      REG: [0]=10 [1]=20  CRC=3EDA

      REG: [0]=10 [1]=20  CRC=3EDA
```

### 判定标准（M4 通过条件）

- 每秒一行 `[M4] 解析 OK ADDR=1 FUNC=0x03 DATA=...`，且 `REG:` 值与电脑端从站设定**一致**；
- **连续 ≥60s 无** `[M4] 超时` / `[M4] CRC 失败` / `[M4] 帧长异常` / `[M4] 地址不匹配`；
- 每 100 次累计打印 `[485] 统计：成功 100 / 失败 0 / 超时 0`（1000 次时误帧 0、丢帧 0）。

> 注：`CRC=3EDA` 是 **CRC 数值**（十六进制字面量）；线上字节序为**低字节在前**，故该帧帧尾实际是 `DA 3E`。二者不矛盾。
>
> 注：若实物为 `MAX485` / `MAX3485`，除接线外还需把 `config.h` 的 `RS485_DE_PIN` 改成 EN 所接的 GPIO 号（默认 `-1` = 不启用方向控制）；固件会在发送前拉高 EN、发完并等满 `RS485_TX_GUARD_MS` 后拉低。

### 失败判读

| 现象 | 可能原因 |
| --- | --- |
| `[M4] 超时 ... RX=0` | 未共地 / `A(+)`、`B(-)` 接反 / MAX13487 未接 5V / `EN` 误接（`MAX13487 / MAX13488` 悬空会关断器件） / RXO 未接入 GPIO20 或分压接错 |
| `[M4] 超时 ... RX=N`（0<N<9） | 波特率或帧格式不一致（须 9600 8N1 无校验）/ 半帧（线缆接触、总线反射） |
| `[M4] 帧长异常 期望 9 收到 8` 且紧跟 `[诊断] RX 帧 == TX 帧` | **自发自收回显 / 总线被占死**：接收器被常开使能（`MAX13487 / 13488` 的 `RE#` 被拉低）或方向控制被固定使能（`MAX485 / 3485` 的 `EN` 接高），先查 `EN` 是否误接 |
| `[M4] 地址不匹配 期望 1 收到 N` | 从站模拟器地址不是 1，或帧错位 |
| `[M4] CRC 失败 期望 XXXX 计算 YYYY` | 从站 CRC 字节序不是「低字节在前」（应为 `低字节 高字节`）/ 线路噪声误码 |
| `[M4] 从站异常响应 FUNC=0x83 异常码=0x02` | 从站不存在该寄存器地址（`0x02` = 非法数据地址），改从站寄存器配置 |
| 一发就收到**自己的请求帧**（`[M4] 帧长异常 期望 9 收到 8`） | 半数情况是单向模块（MAX485 / MAX3485）**未做方向切换**：先读实物芯片丝印确认型号，见上方醒目框 |
| `[485] 回环 FAIL` 出现在 `RS485_MODE_LOOPBACK_SELFTEST = 1` | 该开关只适用于**不接 485 模块**、GPIO20/21 直接短接的场景；接了 MAX13487 时回环会失败，属预期 |

> 三级超时 + 帧长驱动（均在 `config.h`）：首字节 **80ms** → 字节间静默 **4ms** → 收满 **9 字节**立即结束 → 整帧兜底 **300ms**。
> 发送后另有 **2ms** 保护间隔（`RS485_TX_GUARD_MS`）。真实总线上若**稳定丢首字节**，优先把该值调到 **3~5ms** 复测。

> ⚠️ **M4 特有风险：电脑端从站经 USB 转 485 时，字符间隔阈值 4ms 可能过紧。** USB 转串口芯片（CH340 等）按 USB 帧（1ms 轮询、最坏可达 ~16ms 延迟）**批量**交付字节，字节之间会出现数毫秒到十几毫秒的**真空间隙**。固件在“收满预期帧长”之前若遇到 >4ms 的空隙，会按第 2 级（字符间隔）提前判「半帧 → 超时」，典型现象是 `[M4] 超时 ... RX=1~8` 且**每次心跳都超时**——极易被误判成模块坏 / 接线错。
>
> **M4 期间的处置**：把 `config.h` 的 `RS485_CHAR_TIMEOUT_MS` 临时放大再复测。
> **实际经过**：M4 期间用的是 **25ms**；**M5 起已收回正式档位 `8`**（值域 4~8，取上界）。
> 帧长驱动仍是主收帧判据，放大该值不影响正常帧的结束时机。
>
> 附带说明：ESP32-C3 每次复位时 ROM/bootloader 会在 U0TXD（=GPIO21）打印启动日志，这些字节会经 485 模块的 DI 上总线（115200 波特）。通常被从站当作噪声忽略；排查「上电瞬间总线异常」时先想到它。另需目视确认主控板是否带 CH340 之类 USB 转串口芯片且占用 GPIO20/21（带则与 UART1 抢引脚，须改用其它可用 GPIO）。


> 回归自测：改回 `RS485_MODE_LOOPBACK_SELFTEST = 1` + 短接 GPIO20/21，即可复跑 M3 的物理回环自测，
> 用于在怀疑「串口层」故障时快速区分是**串口问题**还是**485 收发器 / 总线问题**。
