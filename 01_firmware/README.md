## 1. 三个工程，只有一个是"业务固件"

| 目录 | 是什么 | 什么时候用它 | 会烧到板子上吗 |
| --- | --- | --- | --- |
| **`esp32c3_gateway/`** | ★ **主工程**。真实采集固件，跑在生产逻辑上 | 日常改功能、烧录、真机联调 | ✅ **是** |
| `pio_verify/` | **编译对照**。用 PlatformIO 编**同一份源码**，比对体积与警告 | 迁移 / 换 core / 换 flags 时验证"产物是否等价" | ❌ 不烧 |
| `rs485_probe/` | **焊接体检**。读 GPIO20 电平，判断焊点通/断/短 | 板子焊完 `poll_ok` 恒 0 时，**没有万用表**也能量出来 | ⚠️ 临时烧，查完烧回主工程 |

> 改代码只改 `esp32c3_gateway/`。另外两个是**工具**，不是分支，**不要在里面加业务逻辑**。

## 3. 两条铁规矩

1. **每批次改动必须 `SELFTEST=0` 与 `SELFTEST=1` 双模式编译**
   —— 只编一种会漏掉另一种的分支错误（批次 3.5 就漏过，回环分支编不过）。
2. **JSON 里同时有"换算值"和 `raw` 原始 HEX**
   —— 固件**确实做了换算**（`频率÷10`、`电流÷100`、`温度−40`、`Pf×0.01`、电量公式），
   **同时**把 78 字节原始寄存器 HEX 一并发出（`raw` 字段）。
   > ⚠️ 这与 `02_docs/16` 第 117 行写的「固件只搬运原始值，不做任何工程量换算」**不一致**。
   > 已登记为待决策 **D-07**（`02_docs/00` §6：「固件同时换算工程量与发 raw —— 与原则冲突」）。
   > **在有结论前，两边都不要改**：改代码会让 raw 与换算值脱钩，改文档会掩盖事实。

## 4. 编译与烧录

见 `PROGRESS.md` §5b。要点：

- **正式链 = PlatformIO**（`pioarduino@55.03.311` = Arduino 3.3.11）；`arduino-cli` 仅作对照
- 烧录前**必须让用户关掉 Arduino IDE 串口监视器**（占口会报 `PermissionError(13)`）
- 串口 = **COM5**（`303A:1001`，原生 USB CDC）
